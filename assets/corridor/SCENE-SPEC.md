# 走廊场景规范（多主题）

本规范以 `assets/corridor/forest/` + `js/corridor.js`（canvas 画家算法）为基线，
约定每个走廊主题（森林、洞穴、荒漠、雪原……）的**资产种类、规格、生成方式、验收标准**。
新主题建目录 `assets/corridor/<theme>/`，并在 `js/corridor.js` 的 `THEMES`
注册表登记资产清单与氛围参数（见第七节"场景主题登记表"），渲染器即可换皮。

---

## 一、资产种类（开放主题必备 6 类；封闭主题见登记表增减）

| 类别 | 文件名 | 变体数 | 格式 | 规格 | 用途与要点 |
| --- | --- | --- | --- | --- | --- |
| 1. 侧景大件（树/岩柱/冰柱） | `tree-side.png`、`tree-b.png`、`tree-c.png` | 3 | PNG+alpha | 竖构图，内容高 ≥900px（渲染缓存 768px） | 两侧五条车道的主体，底边即落地线；三个变体差异要大（干形、冠形、姿态） |
| 2. 地被散件（草/花/低矮植被） | `grass-1..4.png`、`foliage.png` | 5 | PNG+alpha | 单株/单簇，内容高 400~700px（缓存 256px） | 散铺 + 烘焙成密草条带；**根部必须做侵蚀处理**（见生成流程③） |
| 3. 路面低草 | 不出独立素材 | — | — | — | 复用地被中的"无花素株"变体（当前为 grass-1、grass-4），渲染时压矮 0.62、拉宽 1.15。**约定：每个主题的地被包至少含 2 个无花素株变体** |
| 4. 远景剪影（山/沙丘/冰脊） | `mtn-far.png`、`mtn-near.png` | 2 | PNG+alpha | 横条，宽 ≤1024px | 静止背景，只被雾带压暗（far 压暗 0.55、near 压暗 0.4）；上缘轮廓要有起伏，下缘可平 |
| 5. 高空动态件（祥云/飞沙/雪雾） | `cloud-strip.png` | 1 条带（4 簇） | PNG+alpha | 横条，**单簇内容 ≥700px 宽**（近处会放大到数百像素） | 用 2×2 簇包生成 + `make_cloud_strip.py` 拼条带；渲染器按**透明列**自动切簇，簇间留 ≥6px 全透明间隔；以 0.12 视差因子缓慢迎面漂来；另有**独立横向风**（真实时间驱动，默认 5 世界单位/秒，可负值反向）——驻足时云也缓缓横漂，前进时与纵向逼近叠加；漂出 ±900 卷绕边界前 180 单位柔和消散、绕回另一侧淡入 |
| 6. 地面纹理 | `ground-tile.png` | 1 | PNG 不透明 | 512×512 四方连续 | Mode-7 扫描带滚动；色调压深（亮部会抢走草地层次） |
| 7. 天空背景 | 无素材（程序渐变） | — | — | — | 渲染器按天气预设（`SKY_PRESETS`：夜空/晴天/阴天/黄昏/恐怖）绘制垂直渐变，色标 0=画幅顶、1=地平线，每个预设附带大气雾霾色 `haze`（远山/远云/地平线以上雾带都往此色融，晴天=亮天光青、夜空≈黑）、环境光 `amb`（[颜色, 强度]，帧末全屏 multiply，让树/草/地面全局受氛围影响）与联动系数 `cloudCap`/`mtnCap`/`fogUp`；地平线以下雾带恒为黑——尽头的黑暗只属于通道内部。**默认"随时间"模式**：按昼夜表（夜→黎明→晴→黄昏→夜，`DAY_SCHEDULE`）在相邻预设间平滑插值（色标/雾霾/环境光全量混合），天空与全局氛围随推关时钟自动演变；编辑器也可手选固定天气。新主题如需新天气，在预设表加一组色标即可 |
| 8. 日月天体 | `sun.png`、`moon.png` | 各 1 | PNG+alpha | 方构图，内容 ≥500px（缓存 512px） | 昼夜时钟挂在 camZ 上：**一次推关（STAGE_STEP）= +2 小时**，12 关一个昼夜；6:00–18:00 太阳、18:00–次日 6:00 月亮。轨迹为**上拱圆弧、6 步走完**：弧线收在中央天空楔内（约 0.32~0.68 画幅宽，两角被树冠盖死），两端在天空楔两侧半高处（约 0.55×地平线高）、中间拱到画幅顶部（留半张脸余量不裁切）；运动与推进对齐——缓动铺满整个 2h 推进（步进开始起步、结束时就位，smoothstep 峰值速度仅 1.5×均速），战斗期间时钟不走、日月驻留；6/18 点交接各留 0.3h 淡入淡出；画在天空渐变之上、远山之下，会被远山、云、树自然遮挡 |

变体权重约定（地被散铺时的出现概率，森林基线）：
素株为主、花色点缀——`[0.55, 0.05, 0.04, 0.28, 0.08]`，避免"草地变花海"。
新主题同理：主体变体合计 ≥0.8，点缀变体合计 ≤0.2。

上表为**开放主题（有天空）**的完整清单。**封闭主题（洞穴等顶部被实体封死的
场景）**免掉第 5/7/8 类（云/天空/日月）与第 4 类远景（远处只有黑暗），
另加一类**环形切片层**（见第七节 cave 登记项）。各主题实际用哪些类、
文件叫什么名字，一律以第七节登记表 + `THEMES` 注册表为准。

## 二、美术风格约定（style-e）

所有主题统一使用 style-e：**敦煌矿物颜料平涂重彩**。

- 色板：石青、石绿、赭石、土黄为主，点缀朱砂/胭脂；整体低明度、高饱和。
- 造型：深色勾线 + 平涂色块，纸本肌理；**禁止**写实光影、投影、体积渐变。
- 生图背景一律**纯品红 #FF00FF**（`ground-tile` 这类满幅不透明贴图除外），
  画面内禁止出现品红/粉紫色系，否则抠底会误伤。
- 每张图的生成 prompt 存同目录 `<name>.prompt.txt`，便于补件时对齐风格。

## 三、生成流程（四步，产物分层存放）

```
assets/corridor/<theme>/
├── raw/           ① 生图原稿 <name>-raw.png（品红底，只进不改）
├── process/       ③ 中间产物与处理前备份（pre-fray 等）
├── <name>.png     ④ 最终资产（渲染器只读这一层）
└── <name>.prompt.txt  生成用 prompt 存档
```

1. **生图**：按 style-e + 品红底出图，存入 `raw/`。多变体件（地被包）用一张
   2×2 分格大图出齐，保证同批色调一致。
2. **抠底与裁剪**：跑 `scripts/keyout_parallax.py` ——
   品红判定（R>150、B>150、G<110）置全透明，半溢色边缘按品红度衰减 alpha 并去染色；
   然后按 alpha bbox 裁剪（留 2px 边距）、限宽缩放（远景/云 ≤1024，tile 缩到 512）。
3. **根部侵蚀**（仅地被类）：跑 `scripts/fray_grass_roots.py` ——
   对底部 12% 内容带做三层正弦噪声调制的扇贝状 alpha 侵蚀 + smoothstep 羽化，
   消除抠底留下的平直底线。处理前原图自动备份到 `process/pre-fray/`。
4. **接入与验收**：文件名对齐后刷新页面即生效；按第五节清单验收。

## 四、渲染器契约（`js/corridor.js` 对资产的假设）

- **落地锚点**：加载时统一按 alpha bbox 取内容实底，底边即落地点。
  素材四周留多少透明边距**不影响**排版，但内容底边要画到"接地"状态。
- **压暗与淡入**：所有精灵在加载时预烘黑色剪影副本，深度压暗 = 本体 + 剪影
  连续 alpha 两笔。素材本身**不要**画深度明暗，交给渲染器。
- **世界单位参考**（改主题一般不动）：道路半宽 55、相机高 58、
  压暗区 240→1450、树车道 5 条（baseX 122~560）、草条带世界宽 680。
- **密草条带**：加载时把地被印章烘进 2048×176（高草）与 3072×136（路面低草，
  1.5 倍像素密度）的横向条带，环绕式落章保证平铺无缝——这是"茂密"的主要来源，
  单株素材只需管好自身形态。
- **性能预算**：单帧绘制 ≤5ms（当前 forest 全量约 2~4.6ms），静止时零重绘。
  新主题若加大件数量，先量 `window.__corridorDrawMs`。

## 五、验收清单（每次新增/替换资产后过一遍）

- [ ] 无品红残留、无半透明品红描边（放大边缘检查）。
- [ ] 地被根部无平直硬切线（已过侵蚀脚本）。
- [ ] 变体之间差异明显，同批色调一致（同一张分格图出齐可保证）。
- [ ] 云条带簇间有全透明间隔，切簇后无直边。
- [ ] `ground-tile` 四方连续无接缝、色调足够深。
- [ ] CDP 截图双态验证：静止一张 + 前进 1.5s 一张
      （`python scripts/cdp_shot.py <url> scripts/plan_low2.json --out-dir shots`），
      检查：无跳变刷入、无层级穿插错误、无横向黑带、画幅四角无漏黑。
- [ ] `window.__corridorDrawMs` ≤5ms。

## 六、新主题落地步骤

1. 建目录 `assets/corridor/<theme>/{raw,process}`。
2. 按第一节清单（或封闭主题的增减规则）出资产
   （prompt 参考 forest/cave 同名 `.prompt.txt` 改主题词）。
3. 跑抠底脚本、地被跑侵蚀脚本（参考 `scripts/make_cave_assets.py`：
   抠底 + 切片 + 越界碎片过滤 + 去粉残留 + 根部侵蚀一条龙）。
4. 在 `js/corridor.js` 的 `THEMES` 注册表登记（字段契约见注册表顶部注释），
   如需进自动轮换再把主题 id 加进 `THEME_ORDER`。
5. 在本文件第七节登记表补一行登记项。
6. 过第五节验收清单，截图确认后交付。

## 七、场景主题登记表

每个主题一条登记项，格式固定为六栏：**主题 id / 类型 / 资产清单 /
图层结构 / 氛围参数 / 生成规范**。渲染器侧的机读版本在
`js/corridor.js` 的 `THEMES` 注册表，两边必须同步维护。

### forest —— 陆地野外森林（基线，已登记）

| 栏目 | 内容 |
| --- | --- |
| 主题 id | `forest`（`THEME_ORDER[0]`，自动轮换首段） |
| 类型 | 开放主题（程序渐变天空 + 昼夜时钟 + 日月 + 云 + 远山全开） |
| 资产清单 | 侧景大件 `tree-side/tree-b/tree-c.png`×3；地被 `grass-1..4.png`+`foliage.png`×5（无花素株=grass-1/4，兼路面低草）；远景 `mtn-far/mtn-near.png`×2；高空 `cloud-strip.png`（4 簇条带）；日月 `sun/moon.png`；地面 `ground-tile.png`（512 四方连续） |

### 登记格式（后续主题照此填写）

| 栏目 | 说明 |
| --- | --- |
| 主题 id | 目录名 = `THEMES` 键名；进轮换则登记 `THEME_ORDER` 位置 |
| 类型 | 开放主题（天空型）/ 封闭主题（洞窟型），决定第一节清单的增减 |
| 资产清单 | 每类资产的文件名与变体数（素件变体 ≥2 供路面低层复用） |
| 图层结构 | 从天空到环境光的绘制顺序，注明主题特有层（如岩环） |
| 氛围参数 | 雾霾色/环境光/散铺权重/弯道倍率等 `THEMES` 字段的设计值 |
| 生成规范 | 生图约定与处理脚本链（品红底 → 抠底 → 侵蚀 → 尺寸） |
