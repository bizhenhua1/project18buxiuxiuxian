# 局内界面、卡牌与粒子特效

> 后续更新：正式入口的地块归属、直线/岔路编排、行进时收起敌阵、自动遇敌、奖励与统一缩放见[地块、局内路线与遭遇的归属](TILE-LOCAL-ROUTES.md)。该文件覆盖本文较早的固定敌阵空间和统一岔路流程描述。

2026-09-06，本轮实现记录。作者要求：保持原版连续探索和常驻卡牌，重做调试式界面；以小型透明素材拼接；非必要不使用序列帧。本文补充《战斗连续性与表现对照》，视觉方案仍待作者实际游玩评价。

## 不变的核心流程

主岛是长期经营与成长的基地。出征到独立冒险岛，探索地块后进入局内路线。局内景观始终在中央，我方卡牌始终显示。遭遇战停下行进，战后敌方淡出、移除，再继续向前；不会每战切回岛图。岔路、商人、剧情与战斗属于同一路线中的事件。

保留原版法宝手持/操控、站位、血量液面、护盾、冷却环与攻击朝向规则。本轮没有宣称原版数值已经平衡，也没有扩大主岛经营系统的实现范围。

## 布局与验收

- 顶部：地点、当前旅途状态、行囊与归途；删除常驻调试说明。
- 中央：敌阵、冒险景观、随行阵列保持位置稳定。敌方只有实际单位，没有编号空槽；战后显示安静的前路提示。
- 底部：随行整备、当前选中单位摘要、暂歇与行速。完整卡池收进整备面板。
- 岔路、事件、战斗开始、败退恢复按钮只在对应阶段显示，浮在景观上，不挤动上下卡牌。
- 整备区使用原画缩略图、名字与已编入数量；支持收回、重新编入与手持切换。展开时暂停，收起后恢复原先状态。角色不能被移除。

### 作者反馈后的修正：整备与阵容平级

原来的居中弹窗遮挡下方阵容，不符合直接对照、选择和编排的操作关系，已移除。当前整备使用场景内的普通面板，在上方敌阵位置展开横向行囊；中间保留景观，下方我方卡牌保持原位置并持续接收点击和拖放，没有模态遮罩或独立弹窗。

上方可点击法宝编入，也可拖到下方目标位置；选中下方卡牌后，上方详情与持用/收回操作同步更新。空位、角色保护和术法位限制继续由同一阵容规则处理。整备期间暂时收起敌阵和遭遇操作，结束整备后恢复；不允许在交锋过程中修改阵容。

窄窗口仅为上方行囊增加必要高度，缩短中间景观带，保持下方卡牌不移动、不被遮挡。行囊横向滚动，动作按钮与选中说明固定可见。真实输入回放已检查 1600×960 与 1000×650 下的边界、下方点选、上方收回/编入、暂停恢复和随后开战。

卡牌扩大原画可用区域，角色采用上半身取景；原图不裁写。保留不同类型色标和书法名称，增加薄角饰与镂空血槽外环。法宝、投射物优先读取去紫边副本。术法继续使用可读的文字符印，整备列表暂共用小型印饰；尚未为每种术法绘制独立图标。

已查看 1600×960 和 1000×650 的真实引擎截图、场景内整备区、八类法宝/术法阵列、低血量与护盾状态。小窗口会收起卡牌次级模式文字，保留主体、名称和主要状态。整备列表可横向滚动，不把全部内容压缩到同一屏。

## 可拼接资产与严格抠图

AI 生成六个独立小部件：角饰、镂空环、印饰、云纹、按钮端帽、行囊。面板底色、边线、尺寸和文字由界面绘制；不会生成整张界面大图。相同角饰通过镜像复用，按钮端帽两侧拼接。

- 原始图与提示词：`assets/generated/adventure-ui/`。
- 游戏资源：`godot/assets/ui/adventure/`。
- 粒子只用一张 60×52 静态星芒笔触：`godot/assets/fx/particles/spark.png`。
- 初期生成的四格命中图仅归档在 `assets/generated/impact-gold/reference-only/`，运行时不加载、不播放。
- 抠图后去除抗锯齿紫色污染，保留透明孔洞和透明边距；在深色、浅色、蓝灰底上人工复核。
- 七个运行时部件的检查中，强紫色残留像素和外边界非透明像素均为 0。该阈值检查与人工检查配合，不意味着对所有可能背景的数学保证。
- 25 个旧素材另存边缘去污染副本，只处理透明边缘邻域；原文件及 alpha 保持不变。清单记录源文件和副本哈希。

复现处理：运行 `scripts/build_adventure_art.py`。此脚本只做去污染、裁切、打包和检查，不生成原画。对照图与检查结果为 `assets/generated/adventure-ui/cutout-review.png`、`cutout-validation.json`。

## 特效方案：原生粒子优先

采用 Godot `GPUParticles2D` 与共享 `ParticleProcessMaterial`，AI 负责静态笔触素材，运动、发射、透明衰减和生命周期由引擎处理。已经在本机 Compatibility 渲染器下运行。使用正常的一次性发射和 `restart()` 复用，避免 Compatibility 不支持的手动 `emit_particle()` 路径。依据：[二维粒子教程](https://docs.godotengine.org/en/stable/tutorials/2d/particle_systems_2d.html)、[GPUParticles2D 文档](https://docs.godotengine.org/en/stable/classes/class_gpuparticles2d.html)。

| 表现 | 当前实现 | 后续深化方向 |
| --- | --- | --- |
| 普通命中 | 金色短促放射粒子，0.28 秒，结合卡牌受击反馈 | 按武器增加方向性，减少同形重复 |
| 暴击 | 更多、稍大的浅金星芒，0.36 秒 | 独立强调笔触和短促冲击环 |
| 治疗/复苏 | 绿色缓慢上浮粒子，0.65 秒 | 一张静态叶形或灵气纹理，保持数值可读 |
| 增益 | 青色上浮粒子，0.48 秒 | 以轨道/环形发射区区分不同增益 |
| 倒下 | 暗灰散落粒子，0.5 秒，单位变暗 | 按实体/灵体选择碎屑或烟气 |
| 法宝飞行 | 原图沿原版轨迹移动，朝向随轨迹；近战弧线、远程直线 | 稀疏粒子尾迹，避免遮住法宝本体 |
| 光束/法阵 | 动态线条、环形几何与透明衰减 | 用着色器增加边缘扰动，不依赖帧图 |
| 火、冰、雷专属效果 | 保留已有术法表现，尚未完成独立粒子美术包 | 火星/冰屑用静态纹理粒子；雷用分段线和短闪 |

运行时 `battle_particles.gd` 统一管理五种配置与发射器池：12 个发射器，每个最多 12 粒，总预算 144 粒。通常只启用部分粒子，暴击启用全部。超预算丢弃装饰性发射，伤害、治疗和状态计算不受影响。材质复用，事件不会无限创建节点。

暂停将粒子速度设为 0，倍速同步模拟时钟。战后清场、重置会清空池；锚点跟随单位和窗口布局。序列帧不作为默认方案，只在无法通过粒子、几何或着色器实现的特定形变中另行评估。

当前属于可运行的基础特效层，并非所有武器已经有专属美术。144 粒是数量上限，不是帧率承诺；尚未完成手机或集显性能基准。后续应按目标设备测量透明像素覆盖、峰值帧时间和同时命中情况，再调整预算。
