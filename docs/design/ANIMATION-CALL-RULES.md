# 游戏动作调用规范（设计稿）

2026-09-09。依据当前 442 段动作目录、动作转换代码和实机战斗代码分析。本文规定后续实现；尚未替换运行逻辑。目录和时长已核对，命中帧、衔接窗口与双手约束仍需逐段画面标注，不能用名称或统一百分比冒充准确数据。

## 1. 目前存在的问题

- `enemy_actor.gd` 同时承载当前选中主角和敌方模型，`shot/cast` 都播放 `attack`，读取统一 `enemy_3d_motions.json`。换模型不等于换职业。
- 普通伤害直接播放完整 `hit`，会打断正在进行的攻击；频繁受击可能使角色无法展示完整攻击。
- `battle_model.gd` 在行动时生成 shot，按其 duration 结算伤害；近战目前约 0.28–0.45 秒。模型攻击时长和接触帧没有参与这个过程。
- 群攻、溅射和剑系回响可能产生多个 shot。不能把每个 shot 都当成一次新的挥砍、推进一段连击。
- 浏览器骨骼映射通过只说明动作能播放，不说明武器轨迹、脚底、连击拼接、盾牌与双手接触已合格。
- 手指通用握合属于预览辅助。正式动作应优先使用已校准的职业握姿；施法、撒手、投掷时不能始终握拳。

明确的四段候选链：

- 武士 `4_Anim_ARPGSamurai_Attack_Combo1/2/3/4`：0.80 / 0.96 / 0.84 / 1.12 秒。
- 战士 `5_ARPG_Warrior_Anim_rig_Attack_Combo1/2/3/4`：0.80 / 0.80 / 1.00 / 1.00 秒。

## 3. 职业与角色解耦

角色负责骨架、体型和握持校准；武器负责握柄、主副手和接触点；职业动作方案负责动作池、姿态与调用条件。

选择优先级：技能专用动作 → 当前武器与持法的已验收职业方案 → 同武器的通用动作 → 安全待机与效果提示。缺少动作时不要拿长枪动作挥匕首。

建议首批验收顺序：剑盾、武士刀、施法，之后长枪、单手斧、匕首。斧头可借用已验收的单手挥砍，排除刺击；匕首需收紧挥幅与步幅，不能仅把长剑缩小。双手武器必须校准副手接触，否则只保留预览资格。

## 4. 四连击在当前自动战斗中的规则

默认采用“四次普攻依次换招”，不是每次冷却播放完整四连击。

1. 第一次有效主普攻播放 Combo1，第二次 Combo2，依次到 Combo4，然后回到 Combo1。
2. 一次普攻仍只消耗一次冷却、产生原有伤害预算。第四段不额外加伤害、不免费多打几次；需要终结技加成时另立技能数值。
3. 冷却期间收招并回到战斗待机，保留当前链序号。不能为了连续观感提前扣血或加快角色移动。
4. 链序号在本次攻击真正出手（commit）时推进。前摇被硬控取消则不推进；出手后的闪避、免疫或目标死亡不退回序号。
5. 同场战斗普通换目标保留顺序；死亡、复活、离场、换武器或硬控制清空顺序。常规长冷却不以短计时器强行重置，否则慢速角色永远只打第一刀。
6. 单次技能若明确设计成“四连斩”，才独立执行 1→2→3→4；消耗一次技能机会，按技能配置分配总伤害，多段权重总和必须为 1。目标丢失、是否追击和重选目标由技能明确定义。
7. 剑盾 Attack_01–07 先作为候选单招池，经首尾姿态与刃口轨迹验收后编排链；不能先按名字拼起来再让随机混合掩盖问题。

## 5. 一次动作的生命周期

准备 → 前摇 → 出手 → 命中/投射物飞行 → 收招 → 待机。

每次行动有唯一 action_id，携带 source、target、skill、武器方案、连击段和伤害预算。同一次行动的溅射、群攻命中属于同一 action_id，不重复开启动画。回响若是独立追加行为，必须显式标记，不挤占正常普攻链。

命中时间由经过标注的动作事件表提供。模拟层拥有唯一时钟和权威结算；动画只是采样这个时钟，不能由渲染帧回调决定是否扣血。暂停和倍速同时影响两者一次。

- 近战：在标注的接触时间结算该击并播放受击效果。
- 远程：在 release 时间创建弹体，弹体到达后结算，不能抬手时就发射。
- 施法：准备、释放、持续阶段分别标记。持续技能命中次数由技能配置决定。
- 多次擦过目标的武器轨迹不自动代表多次伤害。
- 出手前目标无效：在前摇允许的范围内换目标或取消；出手后不瞬间扭身追向另一个目标。弹体后续是否有效由技能规则决定。

迁移时必须同步替换原 shot 计时结算，不能旧逻辑先扣一次、动画事件再扣一次。原冷却和单次伤害预算保留；命中时序改变需单独回归测试。

## 6. 攻速与打断

动作播放倍率设计起点 0.85–1.25，具体按动作验收；这是播放约束，不是改变游戏攻速上限。

- 冷却足够长：正常播放，剩余时间待机。
- 冷却变短：优先缩减已标注可取消的收招，再选择短招；不压缩关键发力和命中窗口至看不清。
- 极高攻速：使用专门短动作或一段连续动作承载多个独立 action_id 的命中节拍。不能无限排队补播旧攻击，也不能偷偷降低结算频率。
- 未提供适配高速节拍的动作方案不得标记为实机就绪。

优先级：死亡 > 硬控/击倒 > 已授权的技能动作 > 攻击 > 移动 > 待机。

普通小伤默认用上身轻反应或短幅姿态叠加，不打断攻击；没有叠加系统时先用轻效果反馈，不能反复重播全身受击。重击/眩晕是否取消攻击由战斗规则授权，取消时必须同步取消尚未出手的伤害。死亡立即终止后续动作；已出手弹体的存续按技能规则处理。

## 7. 空间移动与状态转换

- 移动路径和位置由世界移动控制器拥有。动作根位移要么提取给移动控制器，要么播放原地版本，不能同时累计两份位移。
- 根据实际地面速度和动作标定步长调整步频。事件距离由移动方式与预算时间规划，禁止为赶事件强拉行走速度。
- 入场使用从当前世界坐标到战斗位的曲线路径，允许前后径向运动；镜头独立减速到预设机位。
- 普攻仅允许小幅、可回收的局部前探；近战不自动横穿战场。需要贴身的技能明确规划去程、攻击与返程。
- 跳跃按起跳/滞空/落地播放，落地由世界高度判断；跳斩只有确实存在空中阶段时才能用。
- 战斗结束后角色向前运动，主角进入移动机位，队友前行并渐隐；2D 道具留在原位渐隐。
- 死亡后停在死亡尾帧；复活清除旧 action_id、队列、淡出与连击状态，再播放起身。没有兼容起身动作时在原位淡入待机，镜头不重新入场。

## 8. 动作数据验收字段

每段至少有：clip_id、骨骼版本、武器/持法、loop、duration、root_motion_mode、blend_in/out、commit、contact/release、recovery_cancel、左/右手接触窗口、是否支持打断、回退动作、验收状态。

contact 和 chain_window 未标注时为 null，不用默认“动作 40%”填充生产数据。`animation-call-profiles.draft.json` 已记录两组四段链的准确资源 ID 与时长，其状态仍为候选。

浏览器后续应支持：连击整组预览；时间轴事件标记；慢放与逐帧；显示武器轨迹和脚底滑移；连续播放两轮；模拟轻伤/重击/死亡/复活；显示本次 action_id 与命中次数。单招能播放不能代替整组验收。

## 9. 实装顺序与验收

先在浏览器标注剑盾与四段链，再做独立动作状态机及 action_id，之后迁移命中时序，最后接入职业与武器配置。不要一次混用全部 442 段。

必须验证：

- 连续八次普攻为 1、2、3、4、1、2、3、4，命中预算仍为八次；群攻不推进多次。
- 普通受击不中断挥砍；硬控取消未出手攻击；死亡后无幽灵出招，复活不继续旧连击。
- 低帧率、暂停和倍速不漏触发或重复触发命中；一次长 dt 跨越事件点仍只结算一次。
- 攻速改变不无限积压动作，慢速角色能打到第四段。
- 左右手、盾牌正反、手指释放、不同模型体型、目标换边、行走到战斗的过渡均检查。
- 单位总伤害与冷却预算符合原规则；只改外观的迭代不夹带职业数值变化。
