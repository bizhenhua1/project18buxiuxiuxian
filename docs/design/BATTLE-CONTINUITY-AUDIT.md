# 战斗连续性与表现对照

> 本轮界面与特效的后续实现见[局内界面、卡牌与粒子特效](ADVENTURE-UI-AND-PARTICLES.md)：六个小部件拼接、法宝整备、透明边缘清理，以及使用单张静态笔触的原生 GPU 粒子池。默认不用序列帧。

日期：2026-09-06。状态：首轮整改已实现，具体范围和限制见文末；下面的差异表保留整改前审查结果。

## 作者此次明确的基线

进入局内地图后，中间景观持续存在，己方卡牌一直显示。战斗在原地发生；胜利后上方敌方单位移除，随后沿当前路线继续向前。一次战斗结束不等于退出局内地图，也不等于完成整个冒险岛。

总体结构仍是主岛经营 → 出征冒险岛 → 地块内的连续局内冒险 → 完成或退出后返回岛图 → 带回主岛。本文纠正此前把探索、战斗和返回岛图拼成独立页面的实现；涉及局内战后去向时，优先于 HOME-AND-EXPEDITIONS、JOURNEY-LOOP 和战斗小样中的旧说明。

## 对照范围与证据边界

- 实际打开原版 index.html，观察方案 2 布阵、开始战斗、战败原地休整和“直接前进”。同一中间景观与己方队列在这些阶段保持显示。
- 检查 js/main.js 的 finishIfNeeded、queueTravelThenRefill、queueTravelThenNextArea 和 refillInPlace：胜利等待在途攻击结算后赶路，赶路结束再补充敌方；原地复位己方战斗状态，不是切换独立战斗页面。
- 本次浏览器运行观察到战败，没有把“直接前进”当作胜利清场的实测证据。当前本地原版的直接前进仍显示敌方；胜利流程也未找到显式清空敌方队列步骤。正式版“胜利后敌方移除”以作者本次明确要求为准。
- Godot 画面对照使用已有 modules-review/battle-05-guard-fighting.png，并逐项核对当前源代码。此截图与原版浏览器尺寸、阵容不同，不能据此做等比例像素验收。

## 已确认的差异

| 项目 | 原版依据 / 作者要求 | 当前 Godot | 修正方向 |

| 攻击轨迹 | 近战二次贝塞尔 + easeOutQuad；远程线性；光束单独分支 | 有素材时一律线性；无素材远程横向正弦偏移；有素材光束被提前 continue 截断 | 先按攻击类型分派，再应用素材装饰 |

## 下一轮实现约束

1. 局内场景持有唯一的路线视图、己方卡牌层和遭遇控制器。战斗控制器管理战斗数据与事件，不负责切换整张地图。
2. 阶段明确为赶路、岔路选择、遭遇、战斗、清场、继续赶路、局内完成。只有局内完成或主动退出才返回岛图；主岛与冒险岛层级不变。
3. 胜利先完成在途攻击及必要命中特效，再清理敌方卡牌/尸体/敌方特效，随后恢复前进。己方卡牌实例、编队、场景视角不得因切换阶段而整体重建。
4. 战斗停下前进速度；环境时间仍继续，保留已认可的分层云漂移、幽暗地平线及森林/洞穴/云海的连续主题转换。
5. 卡牌样式、动作、投射物分别使用配置；弹道以素材前向轴、旋转策略、轨迹类型和时序组成。先复原原版可见行为，再有依据地增强；不靠增加粒子数量掩盖结构问题。
6. 战斗数值平衡另行讨论。修正攻击时间时明确其对战斗结果的影响，不在“美化”中顺带重调伤害或成长。

## 验收顺序

- 先验完整连续片段：进入地图 → 己方常驻 → 遇敌停步 → 战斗 → 敌方清场 → 沿原方向继续 → 下一遭遇。连续至少两场，不要求每场返回岛图。
- 在森林、洞穴、云海各验一次，尤其检验洞穴战斗不会重新变成树林，云的环境运动不会因战斗静止。
- 同尺寸、同阵容、同皮肤分别对照准备、发射、飞行中、命中、残血、护盾、死亡、重聚和战后画面；同时保留短连续片段验证动作节奏。
- 武器朝向覆盖上下左右与斜向，分别验剑、重剑、斧、印、索、镜、葫芦、幡；印与镜旋转、葫芦直立不能被统一朝向规则覆盖。
- 验证暂停、倍速、窗口缩放、最后一发命中后胜负、清场不重复结算、己方卡牌跨阶段实例连续。
- 旧数值与导航测试通过仅证明其覆盖的功能，不能作为“美术达到原版”或“流程符合作者要求”的验收结论。

## 本轮落地

- ExpeditionRoute 直接持有 BattleArena 与同一个 SegmentView。己方卡牌按 UID 保留实例；战斗只暂停行进，环境时钟继续。战败原地休整后可重新布阵；胜利保留短暂清场过程，敌方淡出，1 秒后移除敌方及剩余特效，然后继续行进。
- 遭遇编排存于 godot/data/local_encounters.json。当前右路为两场战斗；左路为旅人类事件加两场战斗。事件后继续走原路线；全部遭遇完成且抵达路段终点后才结算地块收益，仍由玩家选择返回岛图。此数量与间距是验收配置，不是正式内容或平衡承诺。
- local_steps 与 route_choices 一起存档，记录完成的遭遇检查点。中途退出/重启从最近完成的检查点继续，未完成战斗重新准备；不保存逐帧弹道。已完成事件和路段收益不能重复领取。
- 保留敌方区域的布局空间，清场不挤动景观或己方卡牌；事件说明区预留固定高度。卡牌增加类型辉光、等级签、目标边框、手持槽标识、血液高度与护盾叠层、冷却环。血量液面平滑变化；动作分为出击、受击、治疗/增益、死亡后的灰暗和重聚反馈。
- 去除素材的统一额外 90° 旋转；剑/斧/索/幡朝目标，印/镜自转，葫芦直立。近战使用缓出二次曲线，远程线性；光束先分派，随后叠加材质火花，不再被普通素材分支吞掉。次生攻击缩小，命中有短促火花，治疗与增益有扩散环，飘字有分段升落及描边。
- 飞行时长恢复原版公式：近战 clamp(300+d×0.38,280,450) ms，远程 clamp(500+d×0.55,480,720) ms，光束 180 ms、68% 时结算一次，余下时段消散。距离 d 使用固定参考布局（列距 90、敌我排距 500），不随窗口改变。此项改变此前固定 320/420 ms 的小样节奏，但不改攻击、生命、技能倍率及成长数值。
- 增加连续冒险专用验收入口 adventure_preview.tscn / run.ps1 -Adventure，使用独立 adventure-preview.json，不写玩家正式主岛存档。

验证入口：test_continuous_battle.gd / capture_continuous_battle.gd。覆盖两条分支各两场实际战斗、同一景观与卡牌实例、停步与环境时间、暂停、清场继续、事件收益防重、检查点重进、路段结算及 1600×960 / 1000×650 渲染截图。截图存于 godot/captures/continuous-battle。

表现边界：这是可玩且可复查的首轮实现，不代表作者已认可美术达到原版。尚未逐帧等同复现所有原版动画曲线，例如手持模式切换的整套入位/离位动画和血量数字滚动；当前遭遇对手沿用地块敌方配置，后续内容多样性与平衡需单独打磨。
