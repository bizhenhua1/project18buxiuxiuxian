# 森林投影核验与资产重制

## 核验依据

`test_ground_registration.gd` 使用实际运行的地面 shader，在指定世界位置输出测试色标；同时从立绘投影矩形及翻转锚点还原对应落地点。移动摄像机并改变朝向，共 12 个姿态检查实际 GPU 图像中的标记中心。当前最大误差约 0.55 像素。这个证据只支持锚点和地面一致，不代表整张旧树图的深度正确。

旧树的长根包含前伸的地面透视，不能当作同一深度的竖直画片。之后添加的根盘折叠又使用了凭图猜测的深度和二维纹理插值，增加开销且未从根本上保证画面关系。因此移除折叠顶点、根盘几何缓存、特殊绘制，以及已无使用者的贴地四边形代码。树恢复普通立绘路径。

## 当前资产契约

已重新生成两种树：宽冠老树和细长分叉树。要求正面近正交立面、根盘紧凑、无前伸长根、无烘焙地面或长投影、接地线明确。背景透明；保留暗色墨线、青灰叶色。原稿、提示词与旧版运行图保存在 `assets/generated/style2-production/`；重建入口 `scripts/build_compact_trees.py`。

每件树独立记录真实接地点及树干半宽，见 `godot/data/forest_asset_anchors.json`。摆放和地被避让使用树干标注，不再把树冠宽度当占地。配套草与树同组，脚点处于同一接地线，仍在树之后绘制；不会扩展为假地面。当前一般立绘不支持自由环绕观察，这是制作标准的边界。

## 后续验收

先做固定世界标记的移动核验，再检查实际资产，不能仅凭战斗流程通过或静态截图宣称投影正确。新资产必须在前进、停下、左右岔路观察；若出现明显滑动，检查采样点和接地线，不添加经验性时间补偿。

当前森林保留密度、混插、随机镜像与尺度变化。高度场仍使用同一摄像机及世界位置求交；本次没有新增场景运动补偿。


## 摄像机调校（2026-09-07）
森林调校页增加原版视角（58 / .48 / 1）、低机位平视（42 / .50 / 1）、低机位广视野（42 / .50 / .85），分别为机位高度、地平线画面比例、镜头倍率。独立调整即时生效，无需重新撒布，保存与森林设置共用存档。原有存档自动补齐参数，风格 1 不变。
这是直立立绘的透视构图控制，地平线偏移不冒充真实 3D 俯仰旋转。地面 shader 与物件使用同一机位高度、焦距、地平线；不添加树根位移补偿。36 组预设/移动/朝向实测 GPU 地面与 CPU 根锚点最大误差 0.983 像素。

主场景入口：主岛顶部‘森林场景调校’进入，‘返回主岛’恢复原美术风格且保留原出征状态。风格 2 局内底栏‘镜头调校’直接预览和保存镜头，不重建战斗或路线。项目根目录‘启动游戏.cmd’双击打开主岛；启动器兼容本机 Godot 安装位置。集成测试已覆盖主岛进入、返回及实际局内调校窗口。

默认启动修正：project.godot 主场景改为 mistwood_start.tscn，直接进入风格 2 的实际森林冒险，使用独立 mistwood-game.json 存档并读取已保存森林镜头。原 home.tscn 保留。已测试从项目默认入口进入局内且镜头按钮可见。


## 森林 60 帧优化（2026-09-07）
当前纯森林风格 2 使用 ForestBatch + forest_batch.gdshader：原分散纹理拼入运行时图集，树木和根草作为同深度组，静态变换一次生成，GPU 统一进行与地面相同的透视和地形高度计算。没有减少树木、草丛的生成密度，也没有修改用户保存的镜头参数。非森林空间保留原通道。
摄像机参数逐帧提交；透明物件排序在常驻工作线程准备，主线程只接收完成的数据，因此排序可能落后一个准备周期，但树木位置、地面投影不延迟。视域候选带 256 世界单位缓冲。动态怪物使用预留实例槽，避免遇敌时重建整批植物；草丛摆动仍更新少量对应实例。窗口内场景的位置与缩放显式参与 GPU 坐标换算。入场飞卡起点也改为读取当前机位和地形高度。

实测环境：RTX 3060 / Godot 4.7.1 Compatibility，2545×1301，关闭垂直同步测余量；600 帧流程，前 61 帧作为加载和预热不计入。之前另有一份我启动的森林调校窗口在后台，已关闭以避免额外 GPU 竞争。
- 原森林逐帧脚本投影/提交平均约 33 ms（不是整帧指标）。
- 最终正常实际局内：整帧中位 6.85 ms、P95 8.68 ms、最慢 14.93 ms。
- 最终每帧持续改变朝向的压力测试：整帧中位 12.30 ms、P95 15.12 ms、最慢 26.45 ms。正常流程达到 60 帧预算，额外压力下仍有偶发超预算帧，不能保证所有硬件与所有情况无掉帧。
- 回归：完整两场战斗、奖励、返岛通过；36 组 CPU 根锚点与实际 GPU 地面校验通过。后者验证共同投影公式，不等于对全部批量图元的逐像素验证。

图集目前为 4096×8192 RGBA8，含 mipmaps 约 171 MiB 显存；属于桌面方案，后续移动端需按资产实际占用压缩图集。启动仍有一次性图集构建/上传成本，以上稳态结果不包含加载。

批量贴图方向回归修复：QuadMesh 顶点 y=-0.5 对应 UV.y=1，而 Canvas 顶端需要 UV.y=0。此前错误使所有资产上下倒置；现统一使用 1-UV.y 转换，未调整撒布、密度或镜头存档。新增 test_forest_batch_orientation.gd，实际 GPU 采样四个非对称色块，校验上下方向、左右翻转、偏心根锚、非零画布位置和两种朝向。该测试通过，完整战斗回归与截图已重新检查。修正后 2545×1301 正常流程整帧 P95 9.01 ms，最大 14.56 ms。此前的视觉验收漏检此次问题，以本次修正及方向测试为准。
