# 云岫行记：探索与遭遇闭环

> 历史联调样例。作者已纠正游戏结构：主岛是长期经营中心，冒险岛方块应进入局内路线，而非直接接战斗。本文件的「三场战斗后换岛」不再作为正式入口，当前方案以 [主岛与出征](HOME-AND-EXPEDITIONS.md) 为准。

2026-09-06。此轮是可玩的流程样本，数值与奖励仍供讨论；不代表完整养成系统或最终关卡设计。原森林 B、连续空间和浮岛双方案仍保留独立入口。

## 玩家流程

目录选择「启程 · 云岫行记」。点击闪雾探索，或用「向未知处前行」寻找探索前沿；抵达妖息处后布阵、战斗，胜利返回同一座岛并保留探索、阵容和奖励。失败可重新布阵，或回岛后退回来路。平息三处妖息后可前往下一岛。

战斗沿用原卡牌和伤害规则。初始采用护阵示例，第一座岛的三场真实模拟均可获胜。当前全卡试验库仍开放，灵石暂只记录、不消费；后续需另定获取卡牌、成长、消耗和难度曲线。

## 状态与数据职责

- `JourneyState` 管理世界、阵容、遭遇表、已清除记录与行囊。遭遇位置从原始出生点开始按固定邻居顺序广度遍历选取，不能以读档后玩家位置重算。
- 每座岛三个遭遇，按地图编号及序号提供稳定 ID，敌组分别为三、四、五个原敌人；奖励暂设 12、18、24 灵石。
- `IslandModel` 保留原迷雾和寻路规则；到达未清除遭遇时锁定移动、清空后续路径。撤退回到前一安全格，允许重新抵达已探索遭遇。
- 战斗模型发出终局后，行记按遭遇 ID 结算一次。返回探索不重建世界。胜利清除待处理遭遇，失败不发奖励。
- 自动加载节点 `Journey` 负责跨场景持有状态和本地存档。落脚、结算与返回时保存；写临时文件再替换 `user://journey-v1.json`。存档含版本、地图探索、阵容手持模式、奖励和日志。战斗中不保存逐帧战况，重启回到待布阵遭遇。

## 美术编排

浮岛地块继续使用真实 3D 厚度与原 2D 装饰，新增 `IslandAmbience` 环境节点，复用云海纹样，三组高度、半径、透明度与缓慢漂移速度。环境不参与拾取与迷雾可达性，不与冒险走廊的径向云算法混用。深青背景承接原素材的金绿配色。

战斗卡面按透明内容边界裁切显示，减轻素材空白导致的大小不一致；无独立卡图的法宝复用已有相应图形，法术使用双字印记。角色、敌人和法术采用不同底色，增加内框、悬停、护盾与复起进度反馈；同一卡连续跳字错开，减少叠压。

遭遇信息独立于地图图像，侧栏显示原怪物画像和行动；小窗口侧栏滚动，不挤掉地图下方操作。地图未知格的表现沿用前轮，尚未升级为最终体积云遮罩。

## 验证与后续边界

`test_journey.gd` 验证真实探索到三处遭遇、三场战斗、唯一奖励、读档稳定性、手持状态、撤退重返、下一岛门槛、32 张地图的遭遇唯一性、连续覆盖保存。测试和图像回放使用隔离存档，不覆盖玩家行记。

`capture_journey.gd` 使用本机 GPU 记录探索、遭遇、小窗口、布阵、战斗、结算与返回画面。统一运行 `python scripts/check_godot_samples.py --render`。

本轮尚未把森林→洞穴→云海的局内行进嵌入每次遭遇，也未给岛上路径配置相应空间序列；现有类型资源与过渡算法仍在连续空间样例验证。下一步应先由作者确认闭环节奏，再把遭遇前的局内路线接入，避免未经体验确认就批量铺设关卡。
