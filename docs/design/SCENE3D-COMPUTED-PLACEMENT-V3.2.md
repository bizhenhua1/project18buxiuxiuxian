# 从资产内容到布局的计算规范 v3.2

本规范优先规定资产选择、拱架、天花板和补缝的计算规则。v3/v3.1中“根据截图调节”的表述，不能再被理解为默认工作流程。**先做一次源资产语义标注，再计算可行布局，截图只作最终风格和实现错误复核。** 本文为待实现的算法合同，不声称现有代码已经执行这些计算。

## 1. 输入必须少而明确

不是要求模型从一张PNG恢复真实三维。alpha能提供轮廓，不能自动知道哪处是屋顶、门洞、阴影、桌布，也不能从正面确定物理厚度。因此源图只做一次以下人工/辅助标注，之后缓存复用；不反复进游戏猜。

| 输入 | 自动可得 | 执行者查看源图后补充 |
|---|---|---|
| 主体范围 | alpha连通域、边界、有效像素尺寸 | 哪些是投影/碎屑/光晕，应排除 |
| 构件 | 候选轮廓/透明区域 | 左支撑、右支撑、梁冠、墙、树冠、根；不能只标整体bbox |
| 开口 | alpha透明连通区域 | 哪个是可通行主开口、哪个是装饰镂空；开口边界顶点 |
| 落点与连接 | 像素位置 | 实际柱底/根点、墙顶接头、挂点、允许被遮挡的接缝带 |
| 尺度与朝向 | 旧metadata、canvas/visible换算 | 有依据的物理尺寸范围、深度、适用视角区间 |
| 材料 | RGB/alpha与局部候选 | 是否是无透视可重复材料，是否已经画了雾、远景、方向性投影 |

拱架的最小记录：`support_left/right、opening_polygon_xy、crown_band、side_join_bands、visible_bounds、nominal_size_m、allowed_scale、valid_view_cone、source_pixels`。接缝带需要指定可被哪个role覆盖；不能默认所有透明边都是可遮缝区。

这些是独立的 `placement-analysis.json` 设计/分析侧车，引用asset_id与源图hash；当前AssetSpec v2严格schema不直接接收这些新字段。后续适配器读取并编译成runtime profile。图片未改变时不重做轮廓和支点标注。

输出只允许六种决策：`use_as_is / rescale / split_and_assemble / add_backing_surface / add_semantic_trim / remake_required`。每个决策带失败约束、计算数值、要补的具体部件，禁止只写“画面不够丰富”。

## 2. 尺寸不是超过固定米数就废弃，而是求可行范围

设资产标注的名义开口宽、高为Wo、Ho，主体宽高为Wa、Ha；当前通行+镜头包络要求的开口宽高为Wr、Hr。先算粗下界：

`scale_min = max(Wr/Wo, Hr/Ho, 资产允许缩放下界)`。

注意拱洞在肩部变窄，Wo/Ho两个数只能粗筛。最终要把放缩后的**整个开口多边形**与角色/相机截面包络做包含检测；“最高处足够高”不代表左右站位不会撞梁。

上界来自以下约束的交集，而非把图片放大到刚好满屏：

1. `scale <= asset.allowed_scale.max`。缺省对已标定硬结构采用0.85–1.15，对普通家具0.9–1.1（初始设计范围）；需要更大差异应采用新的尺寸变体/拆件，而不是让柱纹、桌腿比例失真。首次标定名义尺寸不受旧代码错误高度限制，但必须记录依据。
2. `scale*Ha <= 场景该构件允许高度`，`scale*Wa <= 该处结构可用宽度`；按部件而非透明画布计算。大树冠可越出通道，树干不可以。
3. 纹理分辨率：沿用已接受的风格采样要求；没有专门要求时，最大投影可见高度P应满足 `源图有效高度 >= 1.25*P`。不满足先远移或换高分辨率源，不能通过插值放大宣称信息已补足。
4. 固定3D面在整段相机轨迹中的观察角度必须落在 `valid_view_cone`；缺省硬结构先按正面法线±20°，薄植被±35°作保守候选。此角度是待源图确认的设计初值，绝不声称单图能自动证明它。拐弯超限则拆出侧件/补厚，不临时朝相机旋转。

`scale_min > scale_max`或多边形包含失败时：先尝试保持柱/家具尺寸、只扩展中间连接面；仍不满足则拆左右柱与顶件；有明显烘焙透视且无法拆用则请求重制。**不得继续扩大整个图或靠雾盖住。**

尺寸例（纯计算示例，非现有资产测量）：名义拱口宽6 m、高4.5 m，需求宽7.2 m、高4 m，允许scale上界1.15，则下界1.2>1.15，整图不可用。可保留两柱并外移、另用连续顶/跨梁连接；不能笼统写“把拱门放大20%”。

## 3. 高拱架怎样错落、密度多少

### 3.1 三种资产先分清

- **平面装饰拱框**：有柱和梁冠，中间透明；仅负责层次，纵向覆盖长度视为0。
- **带厚度的拱跨模块**：确有左右墙、拱顶及前后接口；有效覆盖长度由实际3D模块定义，不能从画布高推导。
- **外部树冠/岩檐**：只负责局部上方围合，允许开放天空；不能直接当闭合室内拱顶。

平面拱框再密也不等于封闭顶面。室内必须另有连续拱顶/低顶背衬；洞穴必须有连续洞壳。顶部是否穿帮由连续结构的覆盖决定，拱架密度主要决定视觉节奏，两者不得混为同一参数。

### 3.2 默认排列

完整主拱左右柱和冠属于同一assembly：同截面、同尺度、同支撑高度，不分别随机错开。采用配方的节距初值D，例如大厅7 m。副壁龛、壁灯、短檐可以左右交错半跨，但不得错动主承重框架。

主拱位置 `s_i=s0+i*D+δ_i`，其中稳定seed生成 `δ_i∈[-0.08D,+0.08D]`，相邻实际间距约在0.84D–1.16D。每一对仍须满足支柱脚印不相交和净空约束；不满足则令该对回到标称位置。相位与资产ID在区块生成时固定。

不随机改变主拱高度和宽度：沿路线的连续截面已经决定它们。允许的“错落”是雕饰/破损变体交替、左右附属物半跨错开、纵向小扰动。曲线上的主拱正交于路线切向；拐弯处相邻主拱夹角初值≤10°，超过则缩小间距或改用分件/连续曲面，不能让两个厚框斜穿。

### 3.3 用投影计算节奏，而非反复截图

已知锁定镜头、世界点和投影矩阵，直接计算 `clip=P*V*world`，经过近裁剪后得到viewport像素坐标。沿顶冠或左右柱相同语义点，计算相邻可见层的屏幕间距g；点在相机后或被近裁剪截断时，先裁剪边段，不能直接除以负w。

首轮设计要求（以有效viewport高度Hpx归一化）：

- 中景相邻拱冠层距优先0.025–0.08 Hpx；首个完整近层可以更疏，远层自然压缩。
- 两层的主要冠线间距小于0.004 Hpx且当前已有连续背衬时，判为冗余远层，可跳过一个**装饰框**或并入远景LOD；不能删连续屋顶。
- 正式镜头中默认希望有3–5个可辨的完整结构层。这是大厅/洞穴初值，不套用于开放庭院或短小房间。

从配方区间内取最多5个等分候选D，对固定镜头关键位和转弯采样求投影间距，排除接触/净空失败的候选；在剩余候选中优先最接近初值且实例少的方案。不是无限迭代密度。没有可行D则返回冲突（例：素材拱冠太厚/近层占屏太大），改资产或分件；不能无上限增加层数。

有厚度模块时，还需 `实际间距 <= 有效纵向长度 - 接缝搭接量`。初始接缝搭接2–5 cm，只在明确隐藏接缝带实施，不产生大面积共面重叠。若美术节距与物理覆盖不兼容，采用连续背衬+独立装饰框，不强迫原模块承担两种职责。

## 4. 顶部是否完整：几何判定优先

### 4.0 固定镜头的顶面视锥包络（标杆场景已落地）

闭合低顶、高拱和连续洞壳必须覆盖**固定镜头轨迹的视锥包络**，不能只按可玩通道的截面宽度生成。为此，每个场景 profile 可声明 `camera_envelope_half_width_m`：它是顶面/拱壳的横向安全宽度，不是可玩通道宽度，也不改变站位、岔路或战斗区域。

生成时将该值换算为运行时单位，作为连续顶网格（`closed_low_ceiling`、`closed_arch`、`cave_shell`）的 `half_width_units`；公共段和已选分支使用同一包络规则，未选分支仍不生成。只扩展连续顶面本身，不新增左右墙、屏幕雾、背景压暗或相机补偿。

当前三个标杆的已验证初值为：`red_cottage=7.0m`、`snow_mirror=7.0m`、`piper_mountain=7.5m`。这些数值需要在固定机位 beauty/diagnostic 捕获中确认顶角无意外背景；若仍有未覆盖多边形，按本节登记结构问题并调整顶面参数或资产，不以装饰雾遮挡。

该规则只解决“镜头包络超出通道截面”的结构缺口。拱框、门洞、岩环等装饰资产仍按下文的 asset assembly、净空和密度规则计算，不能把装饰框数量当作顶面闭合证明。

### 4.1 闭合空间

把应有顶面覆盖的路线/公共厅平面域记R，显式开放的天井、洞口等记O。由连续顶网格的水平投影得到覆盖域C，检查 `(R-O)-C` 是否有未覆盖多边形；面积与最大宽度均报告。结构要求是无意外缺口，数值容差只用于浮点噪声（例如几何焊接误差1 mm），不能把一条可见细缝当“允许漏顶”。

还需验证：面法线/背面策略正确、相邻边焊接或有合法收口、顶壁交界不断开、公共厅单owner、相机有效视锥内不看到生成区块的未封远端。斜拱顶和岩顶用面相邻关系与剖面闭合检查，平面覆盖通过不代表侧向也闭合。

区块预读距离由所有允许镜头的可见范围和远端封口决定，不由截图里“似乎已经够远”决定；可见远端应连接下一已加载区块或合法入口/背景封口。开放出口单独列出，不能把全部missing area都解释为出口。

### 4.2 左右上角能不能用雾

**可以作为风格修饰，但不进入C，不算封闭结构，也不允许承担尺寸不合的补救。**

确定处理表：

| 计算出的缺口/接缝 | 首选实体处理 | 可选美术收口 |
|---|---|---|
| 室内墙与顶没有连接 | 补墙顶面/转角带 | 檐口、梁头、垂布；之后才可轻雾 |
| 拱架外角与连续顶存在风格硬接 | 保留连续顶，补冠/侧连接片 | 暗藤、雕饰、灰尘薄雾 |
| 洞环与洞壁交界平直 | 保留洞壳，补顶岩/根须/钟乳 | 湿雾/尘雾 |
| 森林左右上角过空 | 若preset允许开放则不是缺面；按树冠覆盖目标判断 | 树枝、叶冠、稀薄雾；不补室内顶 |
| 废墟故意开天窗 | 开口O及完整断裂边界 | 碎梁、残布、透入雾；不封死设计破口 |

角雾默认单侧投影不超过画幅8%，每层最大不透明度0.12、最多2层（叠加不透明度约0.226）；只是初始美术预算，现有已接受雾效不强制按此重调。角雾锚定真实墙顶/树冠的世界位置，不能贴屏幕随镜头滑动；不遮挡角色头部或选路方向。若必须加到更浓才“看不到洞”，判定结构未解决，返回实体处理。

## 5. 哪些屋子必须有天花板

先按空间语义选闭合方式，再选美术图片：

| 用途/构造 | 默认 | 明确例外 |
|---|---|---|
| 居所、厨房、仓房、作坊、图书室、后台、钟楼内室 | 连续低顶或梁下连续顶 | 有记录的天井/破顶，进入partial_ruin |
| 宫殿走廊、教堂内殿、石砌大门厅、地下拱廊 | 连续拱顶/穹顶分段 | 露天柱廊应改为local_canopy，不继续叫封闭内殿 |
| 洞穴、矿道、下水道、鲸腹 | 连续环向壳体 | 入口、竖井/裂隙明确定义O |
| 庭院、园径、市场街、桥梁、露台 | 不铺全顶 | 摊棚、藤架、门廊各自拥有局部顶 |

只有横梁图片不改变这一判定。需要顶但缺顶图时，默认简单连续几何+同材质贴图，不能转成“无顶场景”来通过。

## 6. 天花板高度如何计算

所有高度先用世界坐标计算，再转换为相对地面的高度；不能把不同地势的局部高度直接求max。

对当前空间段记录：

- `Y_actor(s,l)`：允许站位/行进轨迹上，所用角色与动画包络的最高点；仅对本场景会用的模型/动作缓存，静态美术任务不扫描全动作库。
- `Y_camera(s,l)`：整个规定镜头轨迹的相机位置及近裁剪四角包络；采样误差需要有界。初始每0.5 m路程/每2°镜头旋转取样，曲线中点偏差>1 cm时细分；这是一遍离线/生成时计算，不逐帧修改顶高。
- `d_beam`：梁向下的最大垂落；`d_hanging`：位于通路上方挂物从顶面到最低点的长度。侧边且不相交通路的挂物不抬高全房间顶。
- `Y_floor`：该段地面范围及台阶；楼上、楼下分室段计算。

如果顶面高度H指“室内表面高度”，则：

`H_required = max(max(Y_actor)+0.35+d_beam, max(Y_camera)+0.20+d_beam, max_under_hanging(Y_actor)+0.35+d_hanging)`。

若吊物扫掠域与相机包络也相交，还必须加入 `max_under_hanging(Y_camera)+0.20+d_hanging`。不存在相应吊物的项省略，不能对空集合求max。

上式是保守的整段标量上界；更紧凑的实现可按实际梁/吊物位置分别求局部包络，不能把没有中心吊物的区段也加上最长链。挂物还需独立避开相机包络，不能只检查角色。

另有主题高度区间 `[H_style_min,H_style_max]`，由已标定门/柱和本房间用途确定并缓存。没有该标定时，以标准人形站高h为尺度给一次初值：住宅约1.7–2.6h，作坊2.0–3.2h，大厅3.0–5.5h，洞穴2.2–5.0h；**这些仅是设计起点，不是把本作角色全部改成人类真实尺度。** 已接受资产/镜头可提供更可靠区间。

`H = max(H_required,H_style_min)`；如果 `H>H_style_max`，输出 `ceiling_style_camera_conflict`，禁止默默抬成十几米高的“小屋”。按顺序：把通路吊物移到侧边→缩短吊物/取消该实例→梁使用更薄且受支持的变体→连续顶抬到相机安全处但用低檐/墙面分区维持构图（仍要满足已声明风格范围）→若仍无交集，提交明确取舍。不得自动改用户已接受镜头。

风格区间若保存为“距地高度”，必须加该室段声明的地面基准Y转成世界高度再比较；斜坡上的局部style约束逐截面检查。不能把绝对H_required直接与相对地面2–4米比较。

拱顶高度不能只用拱冠最高点。对每个横向位置x，设屋顶内表面 `h_roof(x)`，必须有 `h_roof(x)>=h_required(x)`；用开口多边形包含检测或剖面距离检查。左右队员头顶撞拱肩时，优先加大拱肩净空/拆柱冠，不能只继续提高中心拱冠。

## 7. 树根杂草、墙脚碎物如何自动补

补物只处理**合法接触之后的美术接缝**。先按支点检测硬物误差≤2 cm初值；树根浮空10 cm时先修根，不允许堆高草掩埋。

输入：主体支撑点/根轮廓、允许遮缝带、地面法线、通路并集、可用覆盖资产。计算根周长L，若单组覆盖的有效沿边宽为w、希望沿边搭接比例o（初值0.15），则候选数 `N=ceil(L/(w*(1-o)))`，随后只在**需要修饰且非通路侧**的边段生成，不强制围一整圈。

每主体默认上限4组；超过上限仍不能遮住需要的接缝，应请求更宽根部变体/根裙，不继续堆几十棵草。选择高度 `h_cover <= min(允许遮缝高度,主体可见高度*0.12)`，不能盖到树干主要轮廓或门槛。根位采地一次，装饰不随镜头移动。

主题分派固定：森林/花园用草、根、落叶；干燥室内用踢脚线、布边、灰尘/碎屑；洞穴用岩屑/沉积/根须（仅合适区域）；钟楼用底座/链组/金属屑。禁止统一调用“补草”。

没有合适role且接缝只是轻微风格边界，记录为P2装饰缺口，先交付；如果接缝来自未闭合几何，则P0结构修复，不能互相降级。

## 8. 计算结果应直接变成工单

一次分析输出以下固定字段，不写长篇无结论观察：

```text
asset_id + source_hash
semantic_parts + annotated_support/opening/join bands
scale_interval + rejected_constraint
chosen_transform / assembly_split
repeat_spacing + visible_layer_count + view_angle_range
required_backing_surface / required_trim_role
ceiling_required_height + style_interval + clearance_result
decision + exact_missing_part + task_owner
```

优先序：已知结构缺面→直接补结构；尺寸不可行→拆件或退回资产；接触正确但美术边界硬→语义收口；仅氛围略空→可选角雾。每种只有有限选项，不让模型重新设计方案树。

缓存键：源图hash、标注版本、profile参数、路线几何版本、镜头轨迹版本。文档改字、灯色改变或无关地图变化不使几何计算失效。生成时计算，运行时只使用已编译结果。

验收只保留三层：输入合法性与公式/几何检查 → 一次本景实现核对（防止代码没按计算结果执行）→ 正式效果复核。大多数“需要重画还是补顶”的决定应在第一层完成；截图不能证明审美绝对正确，但也不应承担本可计算的尺寸和闭合判断。

## 9. 可直接验证的反例

| 输入 | 必须输出 |
|---|---|
| 只有透明拱框，闭合室内，框再密 | add_backing_surface；不允许报告roof_closed |
| 开口要求scale1.2但素材允许最高1.15 | split_and_assemble或remake_required；不得默认放大 |
| 顶面覆盖缺一块，左右角雾不透明度0.8 | 结构失败；雾不能修复该指标 |
| 住宅所需顶高超过已定风格上界 | ceiling_style_camera_conflict；输出具体多出的米数及冲突来源 |
| 站位中心可过，左右队员与拱肩相交 | 开口包含失败，不能仅按Ho通过 |
| 树根离地0.1 m，覆盖草高0.2 m | 先修接触，不能判add_semantic_trim成功 |
| 故意破顶的废墟，有定义开口O及断面 | 开口区域豁免，但断边/其他顶面仍检查 |
| 相同asset/profile/camera，第二次检查 | 直接复用缓存，不重新截图和标注 |

本版不是新一轮全量测量任务。后续模型先把上述规则应用到正在做的一个房间/一个拱架，给出计算决策并执行；没有必要先写完覆盖全库的自动分析平台。
