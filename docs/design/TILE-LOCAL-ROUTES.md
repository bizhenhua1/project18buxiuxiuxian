# 地块、局内路线与遭遇的归属

2026-09-06，依据作者对窗口占比、路上遇敌、奖励提示和主题错配的纠正。本文件是当前正式入口的编排基线，覆盖早期将多空间演示直接套入地块的做法。

## 归属关系

主岛负责长期经营与准备。出征进入独立冒险岛，冒险岛地块拥有环境语义与内容入口。局内路线是该地块内容的一次展开，不是每个方块都生成一整张带岔路的长地图。路线中的战斗与事件推进此次探索，所得先进入出征行囊，返回主岛时再进入长期资产。

| 层级 | 决定什么 | 当前实现 |
| --- | --- | --- |
| 冒险岛地块 | 环境主题、内容入口、探索难度 | `JourneyState.setup_zones()` 从实际格子读取 `theme`，位置与格子绑定 |
| 路线模板 | 直线/岔路、长度、事件序列 | `LocalRouteSpec` 读取 `local_encounters.json` |
| 空间计划 | 各路段采用哪种环境表现 | 按地块主题生成 `RoutePlan`；普通路线只有一个主题 |
| 遭遇条目 | 距离、战斗/社会事件、有无选择、胜利所得 | 依据当前事件索引推进，已完成索引写入存档 |
| 战斗阵容 | 实际参与战斗的敌方单位 | 路上形象从即将参战的真实阵容中选取 |

**主题、岔路、事件类型互相独立。** 森林里的右路仍然可以是森林，洞穴里也可以有商人；不能用左/右方向推断洞穴/云海，不能把“复杂场景”当成“所有地块都必经的内容”。

当前原型导出的外部地块全部标为 forest，因此正式局内入口全部使用森林。原先“云谷旧道、石关幽径”的命名也改为符合实际环境的名称，避免外部描述和内部环境冲突。

## 普通短路线和显式岔路

当前三个入口用于代表不同编排：

- 林间小径：直线，两次战斗，路线长 1100。
- 林中歇脚处：直线，一次行商事件、一次战斗，路线长 1100。
- 深林岔道：明确配置岔路，左侧事件加两次战斗，右侧两次战斗，路线长 3400；两侧仍为森林。

这些数量、间距和奖励只是当前样本配置，不是最终数值设计。新的短事件可以独立配置序列，增加岔路不应成为增加内容的前提。

直线是真实几何：只生成中间一条道路，树木、草地、空间坐标与地面着色器均使用直线配置。没有只藏起选路按钮、却在前方留下岔路缺口。旧 A/B 与多空间演示仍留在专门的小样入口。

森林通向山洞的跨环境内容仍有意义，但必须由关卡明确放置入口、目标环境和过渡区间。目前跨环境展示保留在 `space_study`，没有给普通地块自动加入跨环境入口。正式的任意门户/跨地块连接仍属后续工作。

## 遇敌与结算

### 必战群体演出与空走节奏

动作细化采用 `CreatureMotion` 共用配置：野猪先短促压低再冲出，小型兽类快速双拍蹿动，蛇横向蜿动，鸟类增加短促上跃，其他兽类使用轻巧跳跃。所有出林曲线共用原有 0.28 秒时隙，端点恢复标准尺寸；不会增加遭遇等待或拉长 0.72 秒入卡过程。卡牌内敌方攻击也使用同一类轻微压缩/伸展，只影响原画，不缩放文字和数值。当前没有老鼠卡牌和原画，小型兽类配置预留给未来接入；已有野猪使用真实素材验收。

出林时，每个实体最多检查预选的 24 个附近草地物件，仅距离 85 内的草响应。草以底部为支点轻摆，0.42 秒内衰减复位，强度随冲撞/蹿动/飞扑区分。大树不跟随摇动，远处草不受影响；暂停统一冻结动物与草的时间。无需序列帧或额外贴图。

没有选择项的必战遭遇会预先生成实际敌阵成员：领头角色在路上，其余成员位于两侧林中。接近战斗点前 200 个距离单位，同伴从左右交替的位置窜入，单次横向运动 0.28 秒、依次相隔 0.055 秒，保留树木与草地的遮挡。然后每个实体从自己的真实投影位置快速进入自己的卡位，沿用同一条连续曲线算法，以轻微时间差展开，不能用与实际敌阵无关的临时怪物充数。

必战群体与带选择事件分开：后者不强制安排整群冲出。标准移动速度从 260 调为 420；距离配置不变时，稳定行走段约缩短 38%。仍保留接近加速，不使用跳过路径或瞬移来压缩时间。当前时序和速度属于可调样本参数。

### 进入局内的耗时修正

本机 Compatibility / RTX 3060 的真实首帧测试发现：原短路线连续三次进入约为 2069、1983、1994 毫秒；后两次场景读取低于 1 毫秒，初始化仍约 1.8 秒。重复拼接草地贴图、远山颜色处理和透明雾遮罩是主要原因。带岔路路线还重复执行七千多个物件的路线投影，单这一阶段使进入仍约 2.18 秒。

现将默认森林的不变结果生成到 `assets/prepared/forest_art.res`，包括草地拼接、纹理与 mipmap、雾遮罩和路线坐标；运行时复用资源，每次仍创建独立的世界与遭遇实体。自定义环境参数保留原生成途径，不共享可变的世界状态。

最终同机首帧实测：首次短路线约 523 毫秒，再入约 262–270 毫秒；随后进入岔路约 247–252 毫秒。该数字从场景实例化开始计到引擎首帧，不含应用冷启动、用户操作与系统调度，不能作为所有设备承诺。

缓存通过原图、参数与生成脚本的哈希清单管理。修改源素材或算法后，运行 `tests/bake_forest_art.gd` 重建；完整检查会拒绝过期缓存。`test_prepared_art.gd` 逐一验证缓存纹理/mipmap 字节与原生成途径一致、路线坐标一致、生成遮罩不污染原图。构建过程中已发现并修复图像引用复用造成的染暗问题。

复测入口为 `tests/benchmark_entry.gd`，报告在 `captures/entry-benchmark/latest.json`，修改前报告保留为 `before.json`。

### 接战表现的连续性修正

路上怪物不再使用屏幕百分比定位、放大。它拥有与场景一致的世界位置、尺寸、高度、环境雾和深度排序：与草地共用 `focal / depth` 投影，脚底在地面高度，前方草丛可以挡住脚部，后方草地不会盖住身体。地面接触阴影与实体一起按深度绘制。

当前通用入场时序已缩短为 0.72 秒，所有敌方阵容共用：

1. 启动时仅记录一次真实投影矩形，以实际首卡原画矩形为终点，使用一条二次贝塞尔曲线。控制点在起点正上方、终点同高度，横向不反向、不越过目标；尺寸沿相同时钟插值。
2. 前 18% 仍通过世界深度排序绘制，保留草地遮挡；随后转入界面飞行层。两层采样完全相同的曲线，不重新采集起点，不再拼接“垂直上升再斜飞”两段动画。起点按窗口归一化，终点由真实卡位计算；抵达后与卡牌原画矩形严格重合。
3. 首卡原画与边框渐成形，再按顺序显现同伴。路上代表角色被排为敌阵首位，身份在整个过程中保持一致。
4. 入场结束后才启动战斗模拟；入场中锁定阵容编辑，暂停和倍速统一控制整个时序。

同一过程平滑展开敌阵、调整景观视区与取景地平线，保留天空和远方道路；下方卡牌不移动。战后释放敌阵空间也逐渐恢复，避免景观突然撑满。此处通过已有 2D 投影参数与视区实现摄像机取景，不额外引入 3D 相机或序列帧。

这套规范关注的是实体身份、空间位置、遮挡和状态交接，不只为火狸增加一段动画。今后的 NPC、商人、宝物等表现也应明确世界实体如何过渡到交互状态，而不是直接切换两张互不关联的画面；各类事件的专用入场尚需逐项制作。

`test_tile_routes.gd` 补充逐帧视区变化、地平线留白、入场前不计算伤害、暂停冻结时序的检查；`captures/tile-routes/*-entry-*.png` 保留真实渲染阶段图。

行进时移除上方敌阵区域，中间景观使用释放的空间，我方阵列保持不变。进入当前战斗路段即准备实际敌方阵容，取消距战斗点 220 才生成的阈值。选取生命与攻击综合权重较高的单位提前存在于远方，受透视、距离雾与草地遮挡；另用 0.35 秒出生渐显，避免短路线或接续事件在可见范围中突然新增实体。当前这是自动选取关键角色的默认规则，后续首领配置可明确指定代表角色。

抵达战斗点后仅停留 0.18 秒，无选择项自动进入上述 0.72 秒接战时序，合计约 0.9 秒；只有配置 `choice` 的战斗才保留操作入口。暂停会冻结接近和自动开战计时。敌阵按入场时序展开，战斗位置不向前推进。

胜利后显示“战斗胜利、灵石增加、已入行囊”，奖励与已完成索引一同保存；敌方淡出清除后继续前进。完成整条路线时显示独立的地块探索奖励。事件所得同样提示。战利品与地块奖励分别计算，界面不提供重复领取按钮，日志保留收入记录。

当前战斗示例奖励为事件配置的基础值加地块难度；尚未做装备掉落与奖励三选一。返回主岛仍沿用已有行囊转入仓储流程。

## 窗口与操作布局

以 1600×960 作为设计尺度，以窗口宽、高中的约束比例统一缩放文字、卡牌、按钮和间距；更宽窗口增加横向空间。局内缩放不修改其他场景或项目全局显示设置。验证尺寸包括 1000×650、1600×960、2545×1301。

探索：景观 + 常驻我方阵容。战斗：敌阵 + 景观 + 常驻我方阵容。整备：上方行囊 + 景观 + 常驻我方阵容。三种状态共享卡牌实例，下方卡牌不因敌阵收起而跳位。整备保持场景内平级区域，不使用模态弹窗。

## 验证

新增 `tests/test_tile_routes.gd`：地块主题归属、三主题纯空间计划、无岔路短线、三种窗口比例、路上形象确属敌方阵容、自动战斗、胜利与最终奖励提示、重复结算保护、同一卡牌实例持续存在。为了快速验证流程，该回放在战斗开始后提高攻击；原数值战斗另由连续战斗和战斗规则测试覆盖。

更新连续路线测试：岔路明确配置，后续区域仍断言为森林；检查跨战斗实例、暂停、检查点重入与分别结算。多空间测试继续验证洞穴和云海演示本身，避免将其与正式地块内容混淆。

真实渲染图和结果：`godot/captures/tile-routes/`。完整回归报告：`godot/captures/validation/report.json`。隔离试玩继续使用 `godot/run.ps1 -Adventure`，不覆盖主岛存档。
