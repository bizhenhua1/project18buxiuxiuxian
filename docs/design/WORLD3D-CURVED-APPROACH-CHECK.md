# 弯道事件接近修复

2026-09-14：接近事件时，旧逻辑直接将主角移向终点，路线进度在抵达前冻结。弯道上会沿终点弦线抄近路，角色实际位置与路线进度不一致。

修复后接近阶段复用行进阶段的曲线路径与距离预算，逐帧更新路线进度；摄像机仍独立按既有缓停曲线到达预定事件机位。没有改动镜头模板、速度值或事件距离。

验证：真实森林 Stage 的左右弯道用例均通过，覆盖逐帧路径贴合、位移不超过速度预算、路线进度单调、事件抵达及镜头停止锚点。事件模型转入战斗的既有用例也通过，包含同一个模型/位置、首次战斗步进连续、池容量与重置。后者补充显式 1440×900 测试窗口，避免无窗口模式下默认小视口使近景投影断言失效。

这是空间与状态验证，未将其当作动态画面最终验收，也没有扩大到所有主题或性能压测。

## 预部署怪物的道路接近

怪物此前也直接沿出生点与终点之间的直线移动。现保存其部署时的路线、支路和里程，沿反向道路接近固定事件位置；出生朝向使用当地道路切线，随后按实际位移更新朝向与步频。玩家跨越流式路段边界不会重新定位已经出现的怪物。仍保留原出生距离、半秒淡入、正常行走速度以及抵达后 idle。

`test_world3d_preview_route.gd` 验证左右弯道、逐帧道路贴合、速度上限、朝向与移动方向一致，以及人为切换玩家路线后怪物保持部署路线；实际事件怪物接管到战斗的回归也通过。连续跑图测试的出生朝向判据同步从终点弦线更新为道路切线，本轮没有重跑整份长期跑图测试。

## 跑走节奏衔接

后续检查发现接近阶段固定使用 RUN，覆盖了行进阶段的步行规划。现在两阶段使用同一个随剩余路程平滑降至 WALK 的速度包络；步行距离在出发时记录，不会因跨路段导致 branch 重置而改变。首段继续全程跑步，镜头刹停提前量与其停止时长对应，避免摄像机完成条件额外拖延首次事件。

实际 Stage 固定 0.025 秒步长、起点位于行进路径的三种用例：首段 3.00 秒（全程跑），普通段 3.55 秒（纯步行约 0.775 秒），岔路后 5.85 秒（纯步行约 1.15 秒）。测试同时要求速度有界且接近阶段不再次加速；左右弯道回归通过。这些时间不含从任意战斗位回归行进路径所需的额外路程，不能声称所有布阵的总耗时完全相同。未更改旧版 TravelPace 参数或保存镜头。

### 完整流程回归后的修正

七个镜头检查点的 GPU 流程发现上述首段 3.00 秒版本存在镜头刹停加速：提前量 .825 秒大于 .8 秒缓停时间，目标距离超出单调减速可达范围。已撤销该提前量；保留 .7 秒跑距作为刹停距离，并从首段总距离中计入 .1 秒的镜头收尾。角色速度不变。

修正后的首段对齐路径用例为 3.025 秒，普通段与岔路段不变。GPU 流程无脚本错误，刹停入口前后速度均为 61.357 路线单位/秒，后续通过单调减速断言；七处截图完成，已查看事件和离场画面。该流程注入胜利结果，不能代表自然战斗通关。离场截图仍有左侧树木底部硬边等资产接地问题，后续应集中处理，不能视作最终美术验收。测试同时改为记录运动失败并返回非零退出码，防止辅助采样函数断言失败后主流程仍打印完成。

### 连续事件的步行刹停

16 事件连续流程进一步发现：步行段仍用 RUN × .7 触发刹停，剩余距离超过较低入口速度可达距离，回退曲线会加速（曾测得约 35 进入、70 路线单位/秒峰值）。触发条件已改为当前移动速度 × .7，镜头时长及角色速度不变。

森林独立 Stage 的 16 事件、一次左岔路、两段路线接续通过：17 次停止采样，峰值/入口速度比 1.00010，无反向拉回，最长行进段约 6.00 秒。真实按钮选择岔路，战斗胜利由测试注入，验证的是连续路线与事件流程，不是自然通关或性能。此前单段时间样本应以这次完整路线的覆盖范围为补充，不能推断全部阵型与所有种子。

补充三岔路直行按钮用例同样完成 16 事件及第二段路线，straight=1，峰值比 1.00016、反向次数 0、最长段约 6 秒；没有自动替玩家选择路线。
