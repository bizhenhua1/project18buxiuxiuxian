# 森林统一技术基准

2026-09-14：按用户纠正，先完成森林纵向切片，再适配其他地图。本文件约束实施顺序，不缩减整体 3D 迁移目标。其他主题的试验开关暂不扩大验证范围。

## 固定参考

我方骷髅转化方案现已接入 health_view：复用 skeleton_fit 的静止骨架拟合和每模型 head_scales，骷髅蒙皮挂到同一角色 Skeleton3D，不另播动画；身体与骷髅共享身体局部静止高度范围。骷髅材质补上原生/传统投影及角色淡出参数；关闭或切回幽灵时隐藏骷髅。已查看森林 25% 血量截图，验证 mode 切换、1.15 头骨参数、蒙皮存在、关闭隐藏和相机/节点不变。沿用原拟合算法，不能据此宣称所有角色的头颈与衣裙穿插均已验收；首次拟合成本、敌方接入、全死亡复活过程仍待处理。

我方模型已接入 saved health settings 的幽灵方案（display=transform, mode=0），颜色、能量、透明度与符文风格取原转化编辑器配置，进度绑定 sim.allies.hp/max_hp，回血反向恢复。保留原生/传统角色投影两套材质入口，关闭效果恢复原材质。直接使用旧透明 shader 曾导致环境合成提亮，现使用覆盖透明保持原生深度通道，并让转化区域绕过不透明环境覆盖；因此透明表达不是与旧 alpha 混合逐像素一致。已查看森林半血截图，验证回血、投影切换、恢复原材质、镜头与位置不变。当前只接我方幽灵方案；骷髅方案、敌方转化、完整死亡/复活效果仍未完成。首次启用会烘焙独立静止高度网格，保留 LOD/蒙皮，未作卡顿或长期内存验收。

原生来敌补上受伤后血条：沿用传统细线色彩和 28px 宽度，仅 health_revealed 的存活未结算敌人绘制，跟随实际头骨投影（含近景角色投影方案），增加 8px 屏幕间隔避免远处贴住头发。单 Node2D 绘制，不给每只怪创建 UI 节点；离战、死亡或屏外不显示。实际 hurt 触发的 75% 比例、零伤不显示、离战及死亡隐藏检查通过，已查看森林单只受伤截图。当前仅迁移敌方血条，不能代替尚未完成的角色血量转化材质接入。

来敌显现补齐传统版 born 时间驱动的 0.7s smoothstep 渐入，原生不再绑定后直接 show。每只怪物以各自出生时刻计算，不因移动/攻击状态切换重播；预部署并接管的事件怪 born=-1，保持完全显示。死亡优先完全显示，避免刚显现即被击杀留下不可见尸体。透明值稳定后不重复上传材质参数。森林实际 stage 的渐入采样、完全显现、出生期死亡和接管不重播检查通过，初始朝向及爬行尸体位置回归通过。尚未据此宣称显现时机和全部动态视觉已验收。

新来敌首次绑定模型时，现根据本次实际移动方向初始化世界朝向；尚未产生水平位移时用模拟 heading。方向经过当前战场到世界的坐标转换，之后仍走原有平滑转向。只作用于新绑定活体，不重置已接管的事件怪物或尸体朝向，避免沿用池中上一只怪物的方向。森林 stage 的左右侧向入场、静止 fallback 和人为残留 yaw 检查通过；本项不是所有行走动画滑步验收。

行进动画对照进一步同步到 `9_EM_Run`、elapsed=1.38，参考已离开动作混合区间。两版独立骨架/重定向，不复制骨骼姿态或缩放；原生只在截图取样时使用同一动画时刻。归一化骨点残差：头 0.005587、腰 0.000478、左右脚 0.012614/0.005487（该机位两脚在画幅外）。已查看同步后的行进截图；主要可见骨点接近，但不是零误差或逐像素轮廓验收。本轮未调整正式镜头/角色缩放，避免把跑步相位差误判成构图问题。

爬行死亡补充验证：实际来敌五种模型（composer、joseph-summer、geisha-thirteen、isabella、composer-george）均通过首帧骨点连续、终态保持及复用后与新建 idle 骨架逐骨一致检查；最大首帧误差约 0.00000126m。终态头高随模型从 0.016 到 0.295m 不等，这不是碰撞/衣裙接地验收。森林 stage 的正常与爬行两条死亡分支均通过死亡位置固定、插值不拖动、动画结束仍显示检查。没有新增性能压测；多模型衣裙与地面视觉仍未据此判定合格。

爬行死亡已增加独立过渡：把当前模型旋转换算进根骨骼，保留死亡首帧世界姿态，再在 0.4s 内混合到现有 knockdown 动画的趴地终态。终态横向对齐死亡时的髋部，避免动画根偏移把尸体拖走；最终姿态缓存，复活/池复用清理换算姿态。composer 独立实模测试首帧所有骨点误差约 0.00000052m，头部终态高约 0.088m；固定节点、尸体保持、复用测试通过。已查看 start/middle/end 截图并修正初版终态向后漂移。不是完整死亡动画播放，而是当前爬姿到趴地终态的混合；其他模型及森林实战动态效果仍需验收。

## 通用标准

| 内容 | 实现约束 | 验收证据 |
|---|---|---|
| 镜头 | 角色占画幅比例、地面锚点、站位、视角沿用正式配置；移动/事件/战斗使用独立机位与连续过渡 | 独立正式版与原生版同机位截图；关键位置测量；连续过程画面，不能只比较输入参数 |
| 空间 | 行进、预部署事件、岔路、敌人、技能共用世界坐标；移动速度决定事件距离 | 连续选路与战斗流程；速度、停点、相邻事件时间；敌人在远处预先存在 |
| 接地 | 地表贴片、直立物件、跨通道结构分型；root 不取整图底边，也不自动取最低不透明像素 | 原图支撑标记与实际三角地面核对；近景运动截图；区分正常遮挡与穿地 |
| 接触带 | 直立物件仅根部局部贴地，上部保持画形；贴片沿地形铺设；跨通道结构按支撑脚与净空处理 | 不统一抬高、不全图压平；支撑不悬空，画面不被地面横切；远近简化可共享缓存 |
| 撒布 | 生成时确定布局和局部避让，禁止每帧重排静态资产 | 种子可复现、分块边界无重复、可见物件不跳变；保持认可的通道密度 |
| 开销 | 分块绘制与回收、模型/特效池、按需空间查询、离屏与远景降频 | 同负载性能前后对照；技能命中/状态指纹一致；池无丢失；单独量测加载与长时间回收 |

## 固定实施顺序

1. 森林正式构图复原：移动、事件停机、战斗、离场，含角色与道具的真实空间关系。
2. 森林完整可玩流程：真实战斗、死亡/复活、选路、预部署、后续地图加载。注入胜利的测试只证明导航与状态衔接。
3. 森林普通与技能压力负载优化。先查耗时主项，禁止通过继续堆局部微优化代替整局达标。
4. 森林近景接地/穿插统一规则及完整过程视觉验收。
5. 上述稳定后，再适配其他主题；只有发现规则不适用的资产类型时，才修改通用系统。

## 当前证据边界

前景深度分组试验结论：对相同正式基准计算像素误差，前景区域（x30..1400/y400..810）未分组MAE11.610/255、分组11.891；左植被10.232→10.537，中央及右侧不变。结合额外16批次，目前没有复刻收益证据，因此不推进该方案到生产，也不再为它追加常规性能压测。保留测试fixture作为隔离工具。像素MAE不是唯一美术指标，更不证明原排序物理正确；此处结论仅是该次分组不能证明值得增加成本。报告：`tempassets/work/forest-depth-bands-comparison.json`。已通过GPU遮挡测试的道具/叶片同优先级修复继续保留。

有限前景深度分组试验：新增测试专用 `fixtures/foreground_depth_bands.gd`，aligned capture 加 `--foreground-depth-bands` 时，仅将横跨道具深度的候选批次按道具深度边界分组；复制实例变换/颜色/自定义数据、共享原材质和网格，不改资产尺寸。当前森林13批替换为29批，520实例，增加16个绘制候选；保存独立 depth-bands 图片/报告。已查看截图，左前景叶片叠加有变化；前景区域与未分组图约32531像素变化>1/255，平均绝对差0.586/255，这仅证明影响范围，不证明更贴近正式效果。试验未接入运行时，仍缺镜头移动连续性、各分组内部排序和帧耗时验收，不可直接设默认。测试筛选当前基准heading=0的世界XZ范围，不能用于任意镜头的生产算法。

森林透明批次候选审计：同机位（当前heading=0）按可见分块AABB横向范围和道具深度筛选，再检查该批次实例锚点是否分布在道具前后。五个道具分别有7/8/7/5/5个候选批次跨越其深度，涉及279/339/274/191/245个实例（相互重叠，不能求和当独立数量）。这说明仅按整批中心排序存在结构限制；AABB与锚点候选并不证明所有像素真的发生半透明重叠。后续优先针对这些前景候选验证深度分组，不应把全部场景拆成逐物件绘制。诊断只在测试运行，不引入游戏逐帧遍历成本；目前没有执行批次拆分，也没有证明内部透明排序已解决。

道具/半透明植被顺序修复：道具原固定 render_priority=-80 晚于植被 -90，导致前方半透明叶片被后方道具覆盖。新增真实GPU测试使用生产道具材质：前方50%红叶覆盖蓝道具，修改前读到纯蓝(0,0,1)，断言失败；改为与植被同为-90后由深度排序，读到(0.498,0,0.502)，正确混合；将叶片放后方也验证不覆盖道具，通过。不增加绘制次数。此修复排除固定优先级造成的错误，不代表大批次植被内部的每片透明排序都已解决，仍需森林整图验证。

道具缩略采样覆盖补齐：Sprite3D 的原生材质与环境材质现在引用同一份带mip纹理；关闭环境着色也使用多级线性过滤。服务单独保留原资产引用供正反切换和诊断，缓存仍由当前场景持有。扩展正反测试连续开关环境着色，验证两路径纹理含mip、材质启停正确、缓存数量不增长，并保留离场位置/透明度验证，通过。没有新增逐帧图像生成。

道具缩小采样修复：原始 style2/book、mask 等导入配置 mipmaps/generate=false；传统 ForestBatch 将图集 generate_mipmaps，而3D道具直接采样无mip源图。已在 prop_atmosphere 内通过现有 texture_sampling 创建带mip的纹理，按源纹理缓存到该场景服务；正反切换同样使用缓存，非逐帧生成。材质初次使用增加纹理副本和mip存储，场景服务销毁时释放，不修改原资产导入设置。GPU同机位角点/灯光断言通过，查看更新图，道具细碎黑边明显减少。按钮测试扩展验证纹理实际含mip、尺寸保持、重复请求复用及离场状态，通过。该修复仅覆盖开启环境着色时的道具材质，关闭环境着色的原生Sprite3D路径仍需独立检查；整体植被遮挡等差异仍未解决。

同机位灯光输入审计：导出正式 combat/biome 参数、lantern_position/enabled、region_tint 和 atmosphere_time，再与3D逐字段比较。发现原对照使用道具 visual_time 代替 renderer.elapsed，使灯光时间差约0.31s、灯高差约0.99旧空间单位。现测试使用真实环境时间，同时补偿 bob 相位以保留原道具浮动状态；不修改游戏运行时灯光。复测 `ALIGNED_LIGHTING_DIFF {}`，道具角点误差仍 <0.001px。新增输入一致性断言。此证据只覆盖列出的输入，不等同于最终像素一致；尚需采样/透明叠加检查。

道具颜色空间排除试验：临时移除 prop shader 的 source_color 提示，当前 Compatibility 同帧道具区域 x650..1100/y510..710 的修改前后逐像素差为0，已撤回试验，没有保留无效改动。与正式截图取内部矩形样本比较，书/灯笼均值偏暗约3–5/255，但面具平均反而略亮；像素差还包含细节采样/透明背景，不能推出统一增亮系数。后续应继续核查灯光输入和透明叠加，不能因为整图观感就统一抬高道具亮度。当前仍未证明道具着色完全复刻。

“道具 · 正反”操作已迁移到3D验证面板，沿用传统默认反面。目前资产中有正反版本的时钟可切换；其余道具不伪造另一面。更换时同步 Sprite3D 纹理、艺术宽高比和环境材质采样，保持世界落点、画面高度及渐隐透明度；本局重开保留当前面，重新加载场景恢复默认，与当前旧版临时操作一致。`test_world3d_relic_face` 通过实际按钮发射验证双向切换及离场期间切换不引起位移/重现。此项不代表道具整套着色已对齐。
