## 1. 项目约束

- 作者认可少量 2D 资产构成的局内冒险与浮空岛两层表现，以及已经打磨的细节。
- 作者不满意现有内容和数值。它们是待讨论的设计材料，不作为正式版必须照搬的规格。
- 迁移质量目标：既有认可表现不退步，并有经作者认可的可见改进。以对照验收落实，不以“换了引擎”推定画面更好。
- 先做表现验证场景，再决定正式实现。平台、画面布局、两层玩法关系仍待讨论。

## 3. 应当保留的表现机制

### 局内冒险

它是深度空间上的纸片投影系统，不是几个固定背景层水平滚动。

| 机制 | 当前实现意义 | 迁移验收重点 |
| --- | --- | --- |
| 针孔投影与道路中心线 | 每件物体按自身深度投影，弯路带动物件位置，相机追随前方道路 | 近景掠过、远景逼近、消失点及弯道一致 |
| 地面与密植条带 | Mode-7 地面；少量草素材预烘成高草和路面低草条带 | 密度与接地感不减；无接缝、条带硬边和近景突然刷入 |
| 深度排序与连续雾化 | 按世界深度排序，颜色连续融入远雾，透明根部保留 | 无层级跳变；保留矿彩线条与软边 |
| 三主题差异 | 森林天空开放；洞穴岩环封顶；云海无实体地面且远方融向亮雾 | 云海不能沿用黑色尽头，洞穴不能漏天 |
| 镜头起停与步态 | 速度包络控制上下颠簸与左右摆动 | 起步渐入、停步余摆；保留舒适度调节 |
| 双时钟 | 赶路驱动昼夜，驻足冻结昼夜；云风按真实时间继续 | 停步后世界仍有轻微生气；昼夜不被长岔路意外快进 |
| 真实岔路 | 多条中心线、外墙与分隔植被构成通路；当前版本选择后会并回旧中心线 | 保留几何通路；缩短显露到可选择的等待；选路后方向持续成立，消除拉回旧主路感（见下方作者修订） |
| 主题切换 | 全黑时等资产就绪再切换，淡出 0.45s、淡入 0.7s | 不出现半旧半新、空帧或曝光闪变 |
| 画幅适配 | 独立全屏与主游戏窄带的岔路间距依据投影重新计算 | 两种画幅分别验收，不能只缩放整张截图 |

### 浮空岛

它是有高度的逻辑网格、自定义投影地台、始终朝向屏幕的独立物件与分层迷雾组成的系统。

- 地块中心绕整岛中心旋转；地台自身角点另走缓动。每次 45°、300ms，局部旋转主要发生在动画中间 40%～60%。这是风格化运动，不能无意替换成普通刚体旋转。
- 地台顶面使用纹理三角形映射，侧面由几何绘制；顶面三角形做扩边以掩盖裂缝。迁移可以改善实现，但必须保持地台比例、厚度与无缝感。
- 山、树、洞口与角色以独立立绘站在地台上；朝向变化后按深度处理遮挡。不能仅用固定屏幕 Y 值排序。
- 点击目标基于当前投影后的顶面三角形，重叠时取最近且可前往的地块；不能将未旋转网格反算当正式点击规则。
- 只有实际踩过的格子登记为已探索；视线覆盖不等于全地貌揭示。未知露岛形、边界闪雾、已知离开视野压暗。
- 行走沿已探索格寻路至一个未知边界格，单步 360ms、缓入缓出、轻微抬身。路径、高度与画面坐标分别保存。
- 悬停透视只在被前景挡住的部分填入半透明颜色，再绘制轮廓；可前往与不可前往使用不同轮廓色。
- 当前背景刻意为空色；存在的天空资产不等于已经启用，不能在迁移中自行铺满云海背景。

需向作者确认：双缓动旋转中的短暂地块分离感、未知格当前云纹、明暗对比与默认镜头远近，哪些是满意表现，哪些属于待优化内容。

## 4. 技术路线建议（待小样验证）

首选 Godot 原生 2D 自定义绘制，保留世界坐标与投影数学，配合局部 shader。理由是它能直接控制现有画面构图、排序、非刚体旋转与透明边缘，迁移变量较少。

| 系统 | 候选实现 | 需要验证 |
| --- | --- | --- |
| 走廊 | Node2D 自定义绘制或分批 MeshInstance2D；道路投影保留；地面反投影 shader；预烘条带资源 | CPU 提交成本、填充率、近景纹理过滤与深度雾 |
| 浮空岛 | 独立 Grid/Height 数据；投影网格绘制顶面和侧面；物件与人物独立绘制 | 旋转全周期、顶面 UV、接缝、遮挡与命中 |
| 迷雾及透视 | 地块状态 shader；必要时使用局部遮挡遮罩或 SubViewport | 多层合成、透明边缘、分辨率缩放成本 |
| 交互与界面 | Control 场景及独立输入路由 | UI 与世界点击隔离；画幅切换不改变逻辑状态 |
| 配置 | Resource 保存主题、资产元数据和镜头参数 | 编辑器预览与运行时一致 |

2.5D/3D 正交相机配纸片是备选，不是禁止项。若后续确需自由镜头或复杂空间交互，可做受限对照实验。但 alpha 混合排序、纸片交叠和不同光照管线可能改变当前表现；需要先证明其收益，不默认它更高级或更好看。

Godot 官方说明：自定义 2D 绘制可用于大量简单对象并缓存绘制命令；3D 透明材质存在排序限制。以上是路线判断依据，不是本项目性能结论。

不直接采用普通 TileMap 等价替换岛屿全部表现；可以使用网格数据工具，但自定义地台旋转与遮挡契约必须保留。不把每棵草都变成独立更新节点；先用条带和批次，按 profiling 决定进一步优化。

## 5. 第一阶段：迁移基线包

第一个交付物应是可对照、可重放的表现基线，不是全量战斗系统的 GDScript 翻译。

1. 封存当前工作区表现版本，包含未提交的岛屿改动。保留原 Demo，另建 `godot/` 工程目录（目录方案待正式实施时确定）。
2. 为走廊导出相机、道路、主题、时钟、精灵布局与随机状态；为岛屿导出格子、高度、物件、迷雾、人物与朝向。跨引擎对照直接读取同一布局快照，避免不同随机算法造成假差异。
3. 记录标准操作序列和固定时间步的关键帧；同时录制正常速度视频，观察起停、转向、闪变和帧节奏。截图无法替代动态验收。
4. 资产按实际运行引用建清单，记录稳定 ID、路径、文件哈希、尺寸、alpha 内容边界、接地锚点、显示比例和材质用途。原图、抠底中间件、最终运行资源分层管理。
5. 确认画幅和目标设备，再锁引擎版本、渲染后端、纹理过滤、缩放策略及帧预算。

资产导入原则：初期用无损资源建立参照；逐类对比过滤、mipmap 与 Alpha Border，禁止全库统一最近邻或盲目打开预乘 alpha。预乘与 shader 混合方式必须匹配。用于缩小显示的树草与用于 UI 的图标不必共享导入预设。

当前目录顶层 PNG 粗查：森林走廊 14 件、洞穴 15 件、云海 12 件；岛屿 base 17 件、feature 7 件、link 3 件。此数是磁盘文件数，包含未启用候选，不是正式导入清单。`data/world-assets.json` 与实际代码存在差异（例如视距、启用地块和天空），不能直接当唯一配置源。

## 6. 第二阶段：两个表现验证场景

按风险安排小样：

1. 森林普通赶路：确认素材导入、密植、透视、雾化和起停手感。
2. 尽早加入森林三岔：验证最难的净空、分隔墙、持续转向与后续路段接续；不能等普通路全部做好后再发现结构不支持。旧版并回行为属于改进对象。
3. 一座固定小岛：包含高低台、山、树、角色与未知格，验证 8 个朝向及旋转中间帧、寻路、点击与遮挡透视。
4. 扩展洞穴和云海，覆盖封顶岩环、亮雾、漂浮件、昼夜与主题切换。
5. 用可配置场景宿主演示两层切换；地点事件与战斗接入以作者确认的玩法关系为准。

表现代码按 WorldState / Generator / Renderer / Interaction / ThemeData 分开；游戏状态通过信号/事件驱动表现。资源、战斗结果与存档不能由动画完成回调随意重复发放。镜头动画时钟与游戏进度时钟分别管理。

旧数值暂存为参考数据；不花费第一阶段预算照搬整个装备、境界、天赋、挂机体系。

## 7. 质量门槛草案

| 维度 | 最低验收条件 |
| --- | --- |
| 构图 | 同画幅、同世界快照、同镜头，路径净空、密度和主体比例达到作者认可基线 |
| 资产 | 无新增品红/黑白边、错误裁边、明显模糊或缩小时持续闪烁 |
| 运动 | 起停、左右转向、岛屿旋转与缩放无突跳；动态视频并排评审 |
| 岔路 | 两岔/三岔及各出口可走；显露到选择的等待明显缩短；所选方向持续成立；普通路→岔路→后续路段无拉回旧主路感、跳层或闪场 |
| 岛屿 | 8 朝向及中间帧无明显破面、错误前后遮挡；屏幕命中与可见地块一致 |
| 探索 | 未知不泄露真实物件；只有踩过才记录；回走、遮挡提示与缩放交互正确 |
| 适配 | 至少覆盖实际游戏窄带和独立大画幅；额外分辨率由目标平台确定 |
| 性能 | 在同设备/分辨率记录 CPU、GPU、整帧 P50/P95/P99、显存、加载与静止开销；帧预算待硬件确认 |
| 改进 | 在无退步前提下，至少一项作者选定的可见改善得到认可；不能仅以代码结构更整洁宣称“更好” |

像素差图辅助查接缝和位移；浏览器与 Godot 的采样、抗锯齿差异不适合用单一像素相等率作为美术验收。投影锚点与时间曲线可做数值对照，最终观感需作者评审。

走廊本次有一个 `drawMs≈2.4ms` 的采样，属于浏览器绘制函数计时，不能当作 GPU 耗时或完整帧预算。Godot 是否更快尚未测量。

## 8. 作者修订：岔路节奏与方向感（2026-09-06）

已确认反馈：现有岔路出现过程偏长；选择后明显感觉回到主路，未形成走向另一方向的体验。作者认可截图中展示的通路视觉目标，但不认可当前全过程节奏与并回轨迹。远景具有目的地/方位意义，某些角度应表达玩家对最终大致方向的选择。作者接受必要的模拟接续，但它不能破坏这一含义。

因此，“保留当前表现”不包含原样保留等待时长和回归旧中心线的路径。

### 原因定位（代码分析）

- `FORK_TRAVEL=1150`，普通 `STAGE_STEP=420`：仅接近岔口的距离就约为普通行程的 2.74 倍，还叠加临近停步减速。实际秒数受模式与速度影响，不能直接按距离比例等同耗时。
- `branchWorldX()` 将选定支路偏移乘以逐渐趋零的并回因子；`chooseFork()` 在前方约 720 世界单位处安排 400 单位的并回段。
- `stepFork()` 令相机追随该中心线，收尾后还将横向残差收回 0。当前岔路主要表达左右偏移再回中，未独立保存选择后的持续航向。平滑曲线避免了跳帧，但没有消除“回到原路”的空间含义。

### 建议算法（待 Godot 小样验证）

1. 将资源预载/远处生成与玩家需要观看的岔路接近段解耦。后台提前准备岔路，以可辨认的构图进入短接近段；选项达到可读条件即可开放，不要求完整走完长距离才允许选择。压缩距离时必须同步重算投影净空、遮挡和淡入，避免岔路突然长出来。
2. 选定支路成为后续道路的基准，保留其位置与切线方向。道路用沿程位置与航向描述，相机平滑跟随路径切线；不再把支路 X 偏移归零作为视觉结束条件。
3. 对象池仍可在后台复用普通走廊，但需进行一致的局部坐标变换：相机、可见地物、后续道路和远景参照一起变换。允许内部局部坐标归零，屏幕投影及全局方向含义必须连续；不能仅将相机拉回旧中心。
4. 远景使用独立的世界方位或目的地参照，按照相对镜头航向投影。转向产生的屏幕移动主要来自角度，远距离地标的平移视差应较小；不可在选路后自动把同一座地标重新吸附到正中。
5. 如设计上需要之后向同一大目的地汇聚，以持续路段中的合理曲率完成；保留一段足以建立选择结果的新方向行程，避免刚选路便立即反向拐回。具体汇聚位置与节奏由目的地设计决定。

小样拆为三个可独立调节的阶段：短接近与辨认 → 选择后转向 → 新方向稳定前进。时长和转角先做对照版本，不作为已确认数值。

新增验收：固定同一入口分别选择左/中/右，比较选择后的路向、近景运动与地标位置；观察足够长的后续段而非只看转向截图。记录“首次看出岔口→可选择”和“点击→新方向稳定”两段耗时（不计玩家思考时间）。测试坐标切换前后投影一致，无突然回中、地标跳位或树墙穿越；同时检查主游戏窄带与独立大画幅。

作者已确认：不同岔路可以采用不同的远景关系，先比较两种小样，不预先统一为一种规则。无论哪种，所选路线必须有可信的方向结果。

### 两种小样的对照规格（已实现首轮森林双岔小样，待作者比较）

共用同一入口、地物布局、地标集合、画幅、接近时长和转向基础参数；支持重置与分别选择左/右路。保持差异集中在地标与路线的关系，不用两套美术制造偏好。两组都必须缩短等待，并在转入后持续显示足够长的后续行程，供观察是否又被拉回旧主路。

| 小样 | 地标与路线关系 | 希望验证的体验 |
| --- | --- | --- |
| A：方位参照 | 山或建筑保持世界位置/方位，选择右路后按相对航向自然移向侧方；必要时可离开画面，不能强制留在正中 | 玩家感觉自己改变了方向，仍能借地标判断所在方位 |
| B：目的地导向 | 分支对应候选目的地，路线切线逐渐朝所选地标展开；地标位置随相机和路线自然变化，不以独立贴图滑动强行居中 | 玩家感觉自己正前往选定目标，选择具有目的性 |

B 组地标的靠近速度依据距离设计：远山不因几秒赶路就明显膨胀，较近建筑可以有更清楚的相对变化。两组都保留新方向，允许有设计意图的后续曲率，不使用立刻回中完成收尾。

比较时分别记录：首次辨认到可选择的等待、点击后的转向响应、方向是否持续、目标是否清楚、是否察觉回主路、镜头是否舒适。作者可以按地点选择 A/B 或在反馈后提出混合规则，不要求全游戏统一。

## 9. 共同设计的讨论顺序

每轮集中讨论少数高影响问题，回答形成“已确认 / 待定 / 待实验”的设计记录。

第一轮已询问：目标平台；浮空岛与局内冒险如何衔接；最不满意的三个体验和最想保留的表现细节。

之后按顺序讨论：

1. 玩家扮演谁、希望体验怎样的修仙历程；一次游玩的起点、目标和结束条件。
2. 局内选择频率、赶路与战斗比例、风险与撤退；浮空岛中的时间、资源和地点选择是否有代价。
3. 战斗中玩家决定什么，主角死亡意味着什么，法宝双模式哪些部分值得保留。
4. 奖励与构筑如何制造新选择；最后再定成长曲线、掉落与资源数值。
