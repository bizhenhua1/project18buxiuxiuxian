## 交付单位

一次交付一个场景包：风格说明、家族配置、源图与提示词、资产标注、组合配置、运行时接入、八个阶段的真实截图、失败项与处理结果。复用原六景的已接受画风和镜头；不得把本景试验修改回原六景。

`families.json` 提供森林、沼泽、矿洞、下水道、鲸腹、宫殿、低顶室内七条路径。场景类型决定结构算法，风格只决定材质、主题物件和色调。工单模板不会把“黑暗裁缝室”当成可以直接发布的完整参数。

## 固定步骤与停止条件

1. **建工单**：执行 `python scripts/scene_production.py prepare --family red_cottage --name dark_tailor_room --style "黑暗童话裁缝室，旧橡木、灰绿布料、黄铜挂灯"`。输出在 `scene-production/jobs/<name>/`，存在同名工单时拒绝覆盖。
2. **逐槽位确定需求**：查看该类的源图与正式效果，填参考路径、真实尺寸、视角、变体数和组合成员。生成的提示词必须进一步填写具体物件与尺寸；不能只将场景名替换进去就批量生图。
3. **复用或制作**：每个槽位给出复用、裁切修整、补图、重制、停用之一。无法满足固定镜头视角的整场景透视图直接停用。源图存档，停用表示撤下运行时引用，不删除仍被其他场景使用的文件。
4. **标注并检查**：执行 `python scripts/scene_production.py inspect <job.json>`。图像hash、alpha可见域、近景分辨率、平铺边差、真实支撑点、非零面积脚印、悬挂点与最低点均须记录。平铺边差只是诊断量，不等于风格合格。输出 `asset-check.json`，缺图/缺标注退出1。
5. **组合**：家具主物与配物共用assembly；柱与冠共用尺寸和支撑基准；吊物以屋顶socket为root。完成支撑与净空计算后再进入layout。不得用一串互不相关的小道具补主物缺口。
6. **接入与撒布**：沿本类adapter接入；结构、组合、低装饰分别使用稳定随机流。先计算所有出口保护区与公共厅，再布局，实例根点生成后固定。现有adapter没有支持的字段必须实现并测试，不能仅写进JSON宣称生效。
7. **真实流程回放**：执行下方capture命令。必须由原场景状态机实际走到入口、两岔、三岔、左右/中央出口与战斗，禁止直接改phase或移动镜头伪造截图。
8. **几何与画面复核**：同一时刻冻结相机、角色和撒布，分别保存正式光雾图及明亮无雾图。先看明显结构缺口、支撑、遮挡、比例，再看风格。任何失败都保留，不用PASS文件或“已拍照”替代通过。
9. **跨区块拼接和负载**：检查旧段→新段连接、材质相位、光雾渐变、实例重复、2/3出口净空及移动稳定性；记录帧时间，不因截图回放成功宣布性能达标。
10. **冻结发布**：全部必需项通过才将工单标为accepted，记录本次代码、资产hash和证据。当前工具不会自动发布新场景，尤其不会按文件存在性修改正式目录。

## 可执行命令

```powershell
python scripts/scene_production.py capture --family red_cottage --godot "F:\GitHub\Godot_v4.7.1-stable_win64.exe\Godot_v4.7.1-stable_win64_console.exe" --output tmp/room-new-run
python scripts/test_scene_production.py
python scripts/scene_production.py fit-frame scene-production/examples/red-frame.json
python scripts/scene_production.py evidence tmp/room-new-run/entry
python scripts/scene_production.py catalog tmp/room-new-run/entry --output tmp/room-source-catalog
python scripts/scene_production.py freeze scene-production/jobs/your_scene/job.json
```

capture也可指定 `--cases=entry,junction3,left,battle`；输出目录必须未存在。其他六类使用其id替换family。一次最多运行一个正式验收Godot进程，避免性能与存档互相干扰。八例成功只表示状态机到达并完成采集。

采集使用隔离存档，不覆盖玩家存档；源代码、实际撒布纹理、地面、顶面和挂灯均记录hash。`evidence`拒绝过期证据。`catalog`输出单资产网页，直接看源图及真实画布尺寸，不必靠暗场截图猜脚点。`fit-frame`在摆放前计算整框是否存在统一缩放解，失败返回非零；当前红屋整框就是一个真实应拒绝样例。

`freeze`是生产包冻结门槛，不自动安装到游戏。它重跑资产检查、校验八种状态及源hash，还要求视觉、岔路、地面、吊饰、物效、过渡、性能的署名结论和证据hash。算法不能判断风格是否满意，明确人工/模型审查责任，不能只填写一个PASS。审核证据过期则拒绝冻结。

## 图片规格

连续地面/顶面：1024²起、无透明洞、无家具和方向性投影、2–4m真实重复周期。结构：2048–3072长边起，完整支撑与开口；尺寸以有效轮廓计，不以画布计。家具：1024–1536长边，明确脚点；低装饰512–1024；碎屑256–512。近处实际投影短边的采样至少1.5倍（当前检查值），更严格的家族规则优先。没有脚点的挂灯不能填假地面footprint。

数量必须同时记录：不同轮廓变体数、每10m实例数、固定镜头可见数。复制、翻转、换色不算新的形态变体。起始配额见原资产手册，但小样例先做必需槽位，不等全库完成才验证。

## 类型特例

| 类型 | 必须单独处理 | 不允许的替代 |
|---|---|---|
| 森林 | 根/干/冠独立语义；根固定；低草深度稳定；岔路保留树隙；风只动可动部分 | 用整图宽度当树根占地，或用天花板封天空 |
| 沼泽 | 岸线、湿地高度、根木、水边簇；萤火与贴地雾预算分开 | 水面穿过实地；所有蘑菇都生成灯光 |
| 矿洞 | 岩环原比例、公共岩腔、分离后的支路环；顶岩/岩根各有接点 | 放大三套完整洞口叠成岔路；钟乳放地上 |
| 下水道 | 沟渠纵坡、边台平面、水口与受水面连接、砌石顶、交汇井 | 用森林地形高度直接决定沟渠流向 |
| 鲸腹 | 有机截面、肋架与膜面分工、附着物、湿润染色、滴落与软组织动态 | 用房间平顶或石洞纹理充当体腔 |
| 宫殿 | 成对柱冠、拱肩净空、壁龛与顶挂饰、厅堂公共区 | 柱冠独立缩放，多个整框在出口重叠 |
| 低顶室内 | 连续公共顶、生活组合、地面支撑、吊灯/链条/帘/悬吊物的挂点与净空 | 加左右墙掩漏顶；过大的壁炉填空；悬挂物按地面根点撒布 |

## 悬挂模块

运行代码：`godot/scripts/world3d/hanging_assembly.gd`。示例使用项目已有通用黄铜灯图及低面数吊链；它是机制参考，不是新主题美术已批准。

顶socket持有整组pivot，链与物件共用旋转。最低点与地面/角色净空检查；默认静止；可选摆角≤2°、周期≥4秒、最多8组动态。新增实时灯默认0。静态挂饰已合为两批，路线相机采样净空已检查；任意相机与角色完整动画扫掠仍须补齐，不得把最低点检查称作完整碰撞验收。

悬吊人形是明确选择的主题装饰，不是敌人；默认不自动撒布，排除战斗索敌与阻挡。布帘可分轻摆片但固定挂点，不能整片billboard面对镜头。滴水要有来源与终止高度，不可穿过干燥地板继续下落。

## 顶部检查边界

`roof_inspection.gd` 对当前相机上30%画面做65条射线检测，生成 `roof-check.json`。这是局部覆盖检查，不证明视平线、侧边、远端、整个过渡路径或所有分辨率均无缺口。原六景中没有独立顶网格的类型不能凭此检测宣称封闭。

低顶公共面用所有分支走廊的并集三角化，纹理相位统一。顶面横向范围由离轴镜头界限与高度差推算；近水平射线不能由有限屋顶覆盖，必须登记远端/结构收口需求，不伪造数学保证。
