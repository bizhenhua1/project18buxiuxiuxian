# 七类场景生产：执行手册

本手册覆盖森林、沼泽、矿洞、下水道、鲸腹、宫殿、低顶室内。`recipes/` 是能编译并在 Godot 中运行的参考资产配方；`jobs/` 是新增资产工单；两者不可混淆。参考配方复用原图及原布局支点，新资产必须另过图片与语义检查。

## 0. 先决定三件事

1. 选物理类型，禁止用森林算法填充房间。细分类型见下表。
2. 选照明策略：open / atmospheric / hybrid / geometric，遵守 LIGHTING-ACCEPTANCE.md。暗部背景、天空盒和雾衔接合法，不要求诊断图完全无空隙。
3. 选资产路线：**兼容换肤**或**改变结构**。兼容换肤保持参考的画布比例、支点、开口、允许视角和布局尺寸，直接使用编译工具。新图开口、占地或高度不兼容时，先拆件/重制，不允许悄悄拉伸后继续撒布。

| 类别 | 生产子型 | 默认照明策略 | 当前运行参考 |
|---|---|---|---|
| 森林 | 密林；稀疏古木通道 | open | forest |
| 沼泽 | 开放菌菇湿地；根木与泥岸 | open | swamp |
| 矿洞 | 层叠岩环；公共岩腔；明亮晶洞 | atmospheric，明亮变体改 hybrid/geometric | crystal |
| 下水道 | 砌石拱廊；沟渠交汇井 | atmospheric/hybrid | sewer |
| 鲸腹 | 肋架体腔；膜面连接腔 | atmospheric/hybrid | whale |
| 宫殿 | 暗色柱拱通道；明亮高拱厅 | atmospheric，明亮厅改 geometric | palace |
| 低顶室内 | 低家具+连续天花；分离梁柱+天花；有吊饰室内 | hybrid，依实际光照调整 | red_cottage |

这些子型是制作选择，不冒充已各自拥有独立验收样例。参考运行覆盖七个主类；选择改变结构的子型须补该结构的证据。

## 1. 从原图而非黑暗场景猜资产

打开 `review/index.html`，选择类型，查看每张完整源图和实际撒布画布尺寸。原图哈希和使用数在对应 `catalog.json`。参考配方保存每张实际源图哈希，文件变化后编译拒绝；不得以同名文件替换而不重验。

- 根、脚、柱脚：标语义接触点；alpha下边界仅作辅助。森林树冠宽度绝不是树根占地。
- 多脚硬物：支撑多边形加实际支点，地形采样残差≤0.02m作为起始门槛；失败先平移选地或合适的小底座，不能让每只椅腿独立伸缩。
- 拱框：分别标两脚占地和中间通行开口；透明中空不是实体占地。
- 悬挂物：顶端挂点、最低点、摆动包围体；无地面脚印。吊链、灯体属于一个组合。
- 贴附物：记录宿主与局部坐标，如管口、壁龛、组织；不能当任意地面物件。
- 地表图：区分真正俯视材质和含透视的落叶/碎石图。后者仍是立片，不能硬压成地贴。

森林/沼泽/洞穴/房间分别按 `production-rules.json` 的具体内容、变体数及图像用途开工单。新生成配额是新资产包的建议起点，不强迫重制用户已满意的全部旧图。

## 2. 风格描述→工单→生成

```powershell
python scripts/scene_production.py prepare --family crystal --name cold_crystal_library --style "冷灰岩石、旧蓝晶体、克制的绘本墨线"
```

逐槽生成的提示词已带类型特例、拼组、根点、岔路和照明限制。执行者再加入从参考确定的物件名称、画布比例、开口/支点位置和物理尺寸，绑定实际参考路径/hash。场景描述不能替代这些输入。

**表面材质**：正交无透视、无道具/投影、全不透明、双轴平铺；1024²起，声明2–4m重复周期。**结构立片**：2048长边起，完整端点，不画整幅透视走廊。**家具**：1024起；**小配物**：512起。最终以最大关键镜头的有效轮廓短边至少1.5倍像素为准，不能靠升采样通过。

一个独立变体一份文件，翻转/换色不计新轮廓。提示词、原始生成图、处理后图、处理步骤和hash留在工单。生成失败最多两次定向修订，之后登记是哪一项开口/视角/材质不满足，给出拆件或替代建议；不得无限重抽。

## 3. 图片与几何检查

```powershell
python scripts/scene_production.py inspect scene-production/jobs/cold_crystal_library/job.json
python scripts/scene_production.py fit-frame scene-production/examples/red-frame.json
```

`inspect`检查文件/参考hash、透明轮廓、像素密度、支点/占地/挂点字段与材质透明洞。实际美术语义要结合原图检查，不能由alpha自动认证。`fit-frame`求可行画布高度区间：

`最小高度 = 必需通路宽度 / (图像宽高比 × 开口宽比例)`；`最大高度 = 可用顶高 / 可见高度比例`。

区间为空则拒绝整框。当前红屋旧整框便是实测反例：7.6m通路需5.127m画布高，3.8m房间仅允许4.092m。当前采用低家具+天花子型，停用不合适整框；不是继续放大房间或改镜头。

## 4. 拼组与撒布

| 类型 | 源码中的参考节奏（20U=1m） | 不能泛化的特例 |
|---|---|---|
| 森林 | 树按区域面积与density采样；灌木中心间隔13–34U/cover，每簇4–11；独立路边低草组 | 树干占地避路，冠层可悬挑；根覆盖草归树组但独立接地；风不移动根 |
| 沼泽 | 冠层基准230U×0.83–1.18；小簇间隔18–48U/(1.7×density_scale)，每簇3–8 | 岸边根木/菌类成群，发光只用指定种；不能每一丛都打灯 |
| 矿洞 | 专用岩环85U层距；小簇18–48U/(1.3×density_scale)，每簇3–8 | 岩环保持比例；横截面重叠先合并公共岩腔；不是拉宽三张岩门 |
| 下水道 | 拱架100U×0.83–1.18；小簇18–48U/(0.8×density_scale) | 沟渠/边台/出水口对应；图中管口不是无宿主的悬空喷水器 |
| 鲸腹 | 肋架130U×0.83–1.18；小簇18–48U/(1.25×density_scale) | 肋架硬结构与膜面分工；软组织附着，硬残骸接地；不能共用脉动变形 |
| 宫殿 | 柱拱140U×0.83–1.18；小簇18–48U/(0.65×density_scale) | 左右柱冠共享尺度，顶肩照明决定补面；旧宫殿部分道具与下水道共享，不算独立宫廷资产 |
| 低顶室内 | 生活小簇34–56U，每簇3–6；主家具260–420U；功能组合300–410U；挂灯9m | 当前顶高3.8m；床组画布3.4m、壁炉3.3m、柜椅组合3.1m；不使用旧8m床组或5m多壁炉 |

以上为现有源码节奏，不是每10米最终可见数。放置后还会经过净空过滤、区域归属与剔除；交付时用运行资产目录记录实际数量。改风格先保留节奏，不能为达数量硬塞失败实例。

所有随机选择在生成时固定；不要按帧重抽位置、朝向、alpha阈值。结构先生成，功能组合其次，小覆盖最后。硬物采用占地与全出口保护区判断；穿插失败不靠调绘制顺序遮盖。

## 5. 岔路与区块衔接

- 森林/湿地：公共空地；保护所有出口的树干/根木占地，不阻止合理的高处冠层覆盖。
- 洞穴：先按横截面走廊重叠分组，公共岩腔唯一owner，分开后恢复独立岩环。
- 砌石/宫殿：公共交汇厅内不叠三整张拱门，柱脚必须落在出口间的可用位置。
- 鲸腹：先共同体腔，再分管；肋根避路，暗部膜面衔接按照明策略验收。
- 低室内：同主题两岔/三岔的顶面先并集再三角化，UV相位连续；不新增左右墙。

选路后未选分支在可见范围内保持原位。支持的旧布局已经由每类adapter处理；新结构不可仅设置一个字符串宣称接入。混合主题屋顶必须按区域裁切并共享边界；当前全路线低顶只用于同主题样例，混合主题必须另验，编译器不能自动把同主题证据用于混合主题。

## 6. 光照、雾与物效

所有类型做同机位正式图/开灯诊断图对照。暗场顶缝在正式图中自然，则记录为可接受氛围衔接，不生成无用顶图。只有正式图或实际支持的灯光变化中暴露的部分才补结构。

灯具默认材质发光与现有环境色，不新增逐灯实时光。森林风根固定，沼泽萤火共享批次；洞穴/鲸腹滴落要有表面来源与地面终点；下水道出水与沟渠位置对应。新增物效先使用已有批次预算，禁止每个装饰独立脚本和灯光。

吊饰实现默认静止，静态链条和灯体各一个MultiMesh批次；摆动最多8组、≤2°、周期≥4秒。地面/角色净空、各分支相机通路的声明横向范围在生成时检查。高度/镜头超出声明范围要重新检查，不做逐帧逐灯射线扫描。帘布和悬吊人形按相同owner/socket规则制作，但不伪称当前已具备专用动态资产。

## 7. 编译并在游戏中预览

```powershell
python scripts/scene_production.py compile scene-production/recipes/forest.json
python scripts/scene_production.py capture --family forest --recipe godot/data/scene_production/reference_forest.json --godot "F:\GitHub\Godot_v4.7.1-stable_win64.exe\Godot_v4.7.1-stable_win64_console.exe" --output tmp/new-forest-review
```

换其他类型时同时替换 family 和配方名。七类都有实际配方。复制配方并改id/style/assets即可建立独立预览包；原图引用不变时完整保留原adapter的裁切、支点和尺寸。新图的target必须在Godot资产目录，hash、画布比例及metadata须通过；明确记录支撑、开口、anchor兼容审查。跨类型adapter、重复绑定、变更未复核图片、错误比例都会拒绝编译。

编译输出是 `preview_candidate`，不是已批准发布。运行时只在指定 `--production-recipe=` 时应用，一次生成时替换，不增加逐帧搜索/重撒布。无参数的游戏路径保持原样。尺寸结构不兼容的资产不可直接塞进兼容换肤管线。

每类：入口、两岔选择、三岔选择、左转、右转、中央分支、战斗机位、战后继续前进。采集通过真实状态机到达；战后样例通过真实胜利处理函数触发，是表现用例，不表示自动打赢了一场战斗。

```powershell

```

打开生成的index.html，可切换场景/镜头/正式或诊断图、查看原尺寸并记录意见。原始PNG、相机、路线、资产hash一并保留。不能仅把接触表缩略图当作原图验收。

## 9. 测试、性能及发布

运行 `python scripts/test_scene_production.py` 与Godot的 `test_low_room_workflow.gd`。生产性能使用同机、同viewport、同路线、同种子比较；CPU/GPU预算不靠对象数猜测。现有 `benchmark_scene3d_p10.gd` 提供统计方式，不能把它旧的forest对比直接当作七类新配方验收结果。

静态新增灯饰应保持2批为主；动态灯饰最多8组；真实新增灯为0。更亮配置、更多动态、50怪物和技能峰值属于额外明确负载，必须记录，不能混同普通场景截图的性能。两轮针对性优化后报告具体瓶颈，不无期限压测。

最后 `freeze <job.json>` 会重新核对资产、八状态证据、视觉/地面/岔路/吊饰/物效/过渡/性能审查签名及证据hash。用户视觉意见没通过时标为待审查，不填accepted。缺图、错误结构或负载失败必须保留具体待办，不能改状态让检查变绿。
