# 二维洞穴：事件空间实测与布局试验

2026-09-23。**研究阶段，洞穴未美术验收，室内尚未开始；不能交 Luna 批量生产。**

后续有限弯道、镜头轨迹与实际行进证据见 [2D-CONTINUATION-TRIAL.md](2D-CONTINUATION-TRIAL.md)。

## 不变的表现路线

洞壁、侧肩、拱顶、地脚、悬挂物由二维源图组织。三维坐标负责深度、行进、遮挡和镜头投影。廉价模型只能是另行验证的局部辅助，不能把整个洞体模型替代图片组合作为默认路线。本轮结构模型数为零；没有新增源图、没有拉伸或裁改源图、没有改变正式镜头。

## 这次实际发现的缺口

原有旅行检查只覆盖根节点周围半径 0.28m、高 1.75m 的采样圆柱。它不能证明战斗单位可见，也没有覆盖所有二维敌人和道具。

把原布局接入真实战斗入场后，侧边两个敌人的声明展示轮廓约有 53% 和 47% 被岩片遮挡。根圆柱检查仍通过。这是**检查范围不足**，不能解释成用户应接受的场景遮挡。

新增 `tools/audit_cave_event_visibility.py`：

1. 保存实际战斗镜头、队列位置、尺寸和逐单位 alpha 图。
2. 对每个单位的有效图像像素，沿实际镜头至其展示平面的射线检查更近的岩片 alpha。
3. 实时模型可能提供透明的替代纹理；这种情况保留整个声明矩形，明确记作保守代理，不能跳过。
4. 研究阶段超过 5% 遮挡即拒绝。这个容许边缘碎石的试验值不是全游戏统一验收标准；当前修改后的实际检查低于它。
5. 这仍不是蒙皮模型的精确可见面积，不覆盖全部技能突进、不同队伍规模或所有战斗时刻。

## 二维布局如何给事件留空间

实现：`tools/compile_cave_event_cards.py`。

- 输入必须是同一布局的实测记录，检查实例位置、尺寸、角色及数量；记录源布局和测量文件 hash。
- 由每个单位的有效轮廓和镜头射线计算沿途需要保留的展示空间；不是把整个事件段扩大成统一广场。
- 左右片按源图每行不透明内缘求最小向外平移；顶片按每列实际下缘求最小上移。保留整图比例、固定朝向和世界位置。
- 局部调整以有限范围的五次平滑函数影响邻近岩片。平移梯度上限为本试验的左右 0.4m/m、顶部 0.2m/m，不是所有场景的规范常数，也不等于用户曾举例的侧视角度限制。
- 如果必要调整侵入岔路对齐区，直接拒绝事件位置，要求事件安排得更远；不得自动扩宽岔口。
- 两侧扩展时，安静的外层顶片需要同步提供横向搭接。使用原顶片的完整副本，保留中央主拱；不把整拱横向拉长。副本有固定厘米级深度差，避免共面深度竞争。
- 地脚和悬挂组在父件布局完成后重新挂接。所有计算在编译阶段进行，运行时不逐帧改变图片或求解布局。

当前测量只对应原有探索战斗队列，**不是新战术防守模式的完整队列/技能容量认证**。本次两侧最大平移约 1.735m / 1.327m，顶部约 0.297m；这些是实测结果，不是批量场景填写的固定尺寸。

## 不能只检查四条屏幕边缘

第一版事件调整让单位露出，却新增一处内部顶角空洞，最多 182 个诊断原生像素。此前的“背景不接触画面边界”检查没有拒绝它。

新增 `tools/audit_cave_background_regression.py`：先验证镜头、视口、镜头参数和阶段一致，再对比诊断背景。旧背景周边只允许 1 个原生像素的容差。新出现的内部背景同样拒绝。它不把原有远端开口算作已解决，不能替代最终围合验收。

第二版加入外层顶片侧向搭接后，实际左路 18 个镜头没有新增诊断背景。仍保留原始远端开口作为未完成项。

结构实例从 1479 增至 1581，增加的 102 件都是同库二维顶片，不增加源纹理；11 张源图全部保持宽高比例。该次战斗首帧总 draw calls 从 218 增至 221，第二秒从 266 增至 269。这是含全场景的两帧计数对比，不能代替 GPU 帧时、显存或压力测试。

## 可复现步骤

1. 在原布局运行 `tools/run_cave_cards_study.py`，增加 `--event-probe`，其余参数保持 `--godot`、`--spec`、`--branch=-1`、`--out`。每次使用新目录。
2. 运行 `tools/compile_cave_event_cards.py --spec <原 fork.json> --capture <原捕获目录> --out <新布局目录>`。
3. 再运行真实捕获，增加 `--event-probe --background-reference <原捕获目录>`。新入口会同时检查事件遮挡和新增内部背景。
4. 手动检视入场、战斗诊断/正式画面。自动检查通过不等于视觉验收。
5. 改动队列、镜头、敌人体型后重新测量；最终应把稳定的队列容量契约作为编译输入，不应每做一种美术皮肤都重新拟合一次。

相关代码：

- `godot/scripts/journey/expedition_route.gd`：统一 `event_entries()` 来源；默认仍调用原事件表，仅研究夹具覆盖。
- `godot/tests/fixtures/cave_cards_app.gd`：单事件声明、真实弧长位置、战斗准入契约、阻止研究结束后进入未编译路段。
- `godot/tests/study_c1_card_fork.gd`：实际战斗入场及两个时刻的测量，不替换战斗计算器。
- `tools/test_cave_event_layout.py`：6 个几何反例检查通过，包括“身体不碰墙但被更近图片挡住”、身后图片不遮挡、透明画布不能算身体、相机后方数据必须拒绝。
- `godot/tests/test_route_event_contract.gd`：已有事件能力、分支归属、对齐位置的检查通过。
