# 2D 主导岔路：独立延续区与可见性分区

2026-09-23。**算法原型，不是已验收美术，不允许交给 Luna 批量生产。**

后续资产变体与悬挂组接入见 [2D 资产库试验](2D-ASSET-LIBRARY-TRIAL.md)，不要把本页基础素材的五路检查挪用于尚未全程验证的新组合。

本轮从直道推进到两岔、三岔和洞口跨越。正式场景、森林、用户存档和正式入口未替换。洞穴结构为原始透明图片构成的固定平面，结构模型为 0；地面仍是普通几何平面。图像不被横向压缩，也不逐帧朝向镜头。

## 1. 本次实际排除的错误

1. **每条支路各复制一套外填充。** 三岔的外填充会进入邻居通道；`cards-fork-3way-02` 的站立包络检查出现 434 次采样相交。把角色通道加宽、把岔口变广场，不能作为默认补救。
2. **把分隔岩排到远处。** 单个窄岩图适合洞口局部，但沿整个支路密排会成为重复栅栏。直排和固定交叉平面都实际渲染过，均未通过美术检查。交叉平面没有被选为默认方案。
3. **只按洞口净宽裁远景。** 岩片不等于理想矩形门框；按矩形裁剪会出现未覆盖的竖向空条。
4. **分区之后只查漏空。** 不漏空仍可能出现两套图片之间的垂直硬接缝。必须检查分界是否被真实共享岩片遮住。

对应证据位于 `scene-production/jobs/cave-c1-benchmark/algorithm-lab/`：`native-cards-fork-3way-03`、`native-cards-fork-3way-crossed-01`、`native-cards-fork-3way-portals-01`、`native-cards-fork-3way-partition-02`。这些是反例，不是可交付版本。

## 2. 空间与显示分工

### 路径

`tools/cave_card_junction.py` 中的 `Junction` 定义两个有限、端点导数为零的横移段：

- 到选择位置以前，是普通单通道。
- 由选择位置进入收窄洞口。
- 从洞口继续短暂横移并重新放宽，随后保持原轴向，允许保留横向偏移。

原型以米为单位，选择段起点 8、洞口 14、轴向恢复点 25。两岔洞口中心 ±1.25、后续 ±3.8；三岔洞口中心 -1.85/0/1.85、后续 -4.4/0/4.4。**这些是此原型的输入，不是所有类型的生产标准。** 真实角色队列、弧长速度和事件区仍待接入，不允许拿本次相机采样冒充正式行进控制器。

### 图片分组

| 组 | 可见职责 | 生命周期 |
|---|---|---|
| 共享近景 | 原单通道、岔口外侧、洞口分隔岩与根部过渡 | 继续按普通世界分块裁剪 |
| 共享顶部 | 连续顶层以及遮挡分区接缝的顶片 | 不按竖条切开；不计为某支路内容 |
| 支路延续区 | 该支路的两侧、装饰及后续内容 | 洞口前分区显示；选定后保留自己的内容，安全时卸载其他支路 |

完整支路恢复普通单通道拼组。**不把狭窄的分隔岩配方延续到整个后续场景。** 各延续区的外围填充可以在存储坐标上相交，但显示和逻辑归属必须隔离；不能同时将互斥的岩片作为同一角色的碰撞物。当前原型只演示图片可见性，正式实体/事件的归属开关还没有实现。

## 3. 如何分区，为什么没有额外渲染三次场景

沿用单个相机、单个深度缓冲。每张图片记录 `owner_branch`；共享组为 `null`。

对洞口前的片元，把“相机到该片元”的射线与洞口平面相交。交点横坐标属于哪个洞口单元，该支路的片元才保留。单元分界取相邻入口中心的中点，最外侧单元向外延伸；不能把单元误当成互不相接的净门宽矩形。

```text
t = (洞口 z - 相机 z) / (片元 z - 相机 z)
交点 x = 相机 x + t × (片元 x - 相机 x)
分界 x = (相邻入口中心 x 之和) / 2
```

片元只是有条件地绘制原图片；不拉伸 UV，不需要为每个洞口生成低清截图，也不增加多相机渲染目标。此原型的着色器实现位于 `godot/tests/probe_cave_algorithm_lab.gd`，尚未接入正式 MultiMesh 管线。

分界是显示规则，不是可见线条：

- 分隔岩必须在同一个洞口平面上遮住分界。放在平面后面几十厘米，会在横移中与分界错开。
- 顶部保持共享。切开顶部会在柱顶以上留下拼接线。
- 检查器沿实际分界的投影采样，并扩大两像素余量；若第一命中来自某个延续区而非共享遮挡，判为接缝暴露。
- 进入选中洞口后，相机已经处于该单元内；该支路取消分区限制，其他支路不再显示。相机不会为这个效果突然转向或跳位置。

## 4. 未选支路什么时候能够卸载

不使用“选完后等 1 秒”之类计时条件。

在固定主轴镜头下，根据实际宽高比和倍率计算整幅画面的水平射线范围，投影到洞口平面。只有整个范围都落在选中单元内部，且留有余量，其他支路才能退休。洞口之后也满足此条件。

`retirement_safe()` 实现此规则。离线检查比较退休前后的第一命中对象和深度；原生检查在同一相机位置隐藏未选节点，比较完整 RGBA 字节。

**范围限制**：本轮只验证固定镜头朝向、声明的镜头轨道和两套镜头高度/倍率；不允许推广为任意旋转相机的剔除算法。正式流式加载、资源释放、重新开始与存档恢复尚未接入。原生试验中的隐藏不等于已经实现内存卸载。

## 9. 实际游戏接入：发现的耦合及修正（2026-09-23）

独立入口 `godot/tests/study_c1_card_fork.gd` 已接入原行进角色、实际地形、镜头、光雾和选择界面。结构仍全部由 2D 图片组成，无洞体模型。测试脚本和四个 `tests/fixtures/cave_cards_*` 文件隔离正式场景与存档。当前只跑一次无门岔路，主动排除事件和战斗，不能冒充整局已接通。

### 9.1 合批与深度顺序是可见性合同的一部分

按原纹理/空间块再分支归属合批，纹理共享；同一图片不同归属使用小的材质副本和固定归属参数，避免把逻辑归属塞入颜色透明度。退休时真正移除未选分支的批次节点，不只是隐藏。共享屋顶和仍被其他实例使用的纹理保留，这不等于全部 GPU 资源已卸载。

首次实际游戏测试退休前后有顶部像素变化，不能把它解释为动画误差后忽略。定位到**相邻支路的共享冠部复制在完全相同的深度**：移除不可见批次也可能改变剩余不透明物体的绘制顺序，同深度的岩片会换一个胜出。只改相机射线或归属编码均没有消除问题。

修正：编译时按组的分支编号，为共享冠部增加固定的 `0.045m × branch` 纵深错位，门口分隔岩保持在门口分区平面上。它是当前近远裁剪范围和素材组合的已测研究值，不是所有场景通用常数；远裁剪距离、层厚或模型比例改变需要重新验证。不得用每帧改深度或依赖绘制顺序替代固定空间关系。

- `game-card-fork-left-01` 有着色器编译错误，全部画面证据无效。
- `game-card-fork-left-02` 至 `06` 的退休图像不一致，均为失败候选，早期脚本的零退出码不代表通过。
- `cards-fork-3way-depth-order-01` 保留离线 69 机位检查；`game-card-fork-left-depth-01` 与 `game-card-fork-right-depth-01` 的实际游戏退休前后 RGBA 一致，各移除 56 批、616 实例。没有据此声称艺术完成或稳定帧率。

### 9.2 地脚装饰跟随“落地部分”，不能跟随整张图

新检查 `tools/audit_cave_actor_clearance.py` 使用实际角色根位置和实际地形校准后的岩片，不再只检查镜头中心。采样为半径 0.28m、高 1.75m、离地 0.10m 起的站立圆柱；它不包括摆动的手、衣裙和连续扫掠，检查范围必须保留在报告中。

旧地脚算法按父图全部不透明范围配碎岩，左肩上方的内伸部分也计入地脚宽度。实际左转查到一次碎岩侵入角色路径。现在按父图**已占用高度最下方 10% 的有效像素**计算支撑宽度与中心；碎岩保持源图比例，并跟随这个支撑中心的位置/固定朝向。左右肩的支撑中心通常不在画布正中，不能只缩小宽度而不移中心。

`cards-fork-3way-bearing-01` 包含上述两项修正。`game-card-fork-left-bearing-01` 通过本轮 15 个实际游戏机位的边界背景检查、149 个实际角色轨迹样本检查和退休 RGBA 比较；远端未完成的开口仍单独记账。随后中路试验发现另一个必须独立处理的队列问题，见下节。

### 9.3 队列与窄口相互约束

旧行进构图把队长恒定放在镜头左侧约 0.626m、前方 1.6m。镜头轨道即便无碰撞，中路人物仍会碰到左侧分隔岩；`game-card-fork-middle-bearing-01` 记录了 12 个相交样本。这是失败案例，不能因为左右路可过就放行。

试验场景增加明确的队列策略：角色脚下位置取线路上向前的弧长采样，而非把摄像机的轨道位置加一段直线；进窄口时，原有肩部构图的横向偏移用与通道收缩相同的五次平滑函数减至 0，通道恢复宽度后再恢复原偏移。目标位置交给原有移动控制器，不直接改模型位置；镜头视角、倍率不变。正式 `SceneFormation` 只有可选策略调用点，只有本试验场景实现该方法，其他场景仍走原构图。

`game-card-fork-{left,middle,right}-formation-01` 各有 15 个实际游戏机位。实际角色轨迹样本分别 149/143/149，相交检查均为 0；边界背景检查均为 0。截图只证明已记录的机位，手臂和衣裙完整扫掠尚未认证。试验保持未验收状态。

### 9.4 图像比较的量化容差必须明示

原生研究的简单无光试验可以逐字节相同；正式光雾游戏的中路退休对比出现了极少量 **8 位 RGB 单通道 1 级**差异，轮廓 alpha 无变化。早先失败案例则有约一万像素、最高 86 级的顶部变化，性质不同。

实际游戏入口保留 `rgba_identical` 原值，并另写 `retirement-comparison.json`，统计最大通道差、变化像素数、alpha 是否一致。当前数值容差是每个 RGB 通道最多 1/255、alpha 必须完全一致；不能把结果称为“RGBA 完全一致”，不能扩大容差容纳轮廓跳变。`game-card-fork-middle-formation-01` 实测只有 1 个像素 1 级变化，其几何删除不变性还有前述离线射线检查作独立支持。

### 9.6 本轮收口与下一项工作

机器可读汇总（包含各 manifest 校验和）：`scene-production/jobs/cave-c1-benchmark/algorithm-lab/game-travel-summary.json`。基础七项可见性回归和 `test_cave_c1_route.gd` 通过。**到此停止对相同五条路线重复捕获；除非有新的资产、算法或已定位问题需要复核。**
