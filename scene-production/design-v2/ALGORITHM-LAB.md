# 先算法原型、后美术生产：执行中的验证工作流

2026-09-23。**本页记录可复现研究，尚未完成洞穴艺术验收或室内标杆。**
用户要求：由执行者自己比较、淘汰和验证，到满意再交付测试入口；失败原型不得转交用户充当第一轮质检。

**2026-09-23 方向纠正：立体短拱覆盖整条通道的候选暂停。** 用户指出过度依赖 3D 模型，检查贴材质结果也确有连续套拱的机械重复。以下立体网格证据只证明该研究候选的局部空间性质，不代表最终美术路线。继续工作必须回到大量 2D 资产构成主要画面，3D 仅作有明确用途的局部辅助；不得用“先全模型、最后添图片装饰”规避。详见开发需求第 1 节。

## 1. 此次与以前的区别

原来把真实资产、镜头、路线、透明排序和撒布同时改动，截图不合格时无法定位原因。现在严格分层：

1. 空间合同：通行域、镜头、分支和事件能力。
2. 廉价表示：无限薄的透明轮廓、短厚拱体、随路线变化的短拱体、短拱体加岔口中央岩体。
3. 离线批量拒绝：同一镜头和路线比较，保留失败输入和结果。
4. 留出验证：更密且不同位置的镜头，额外的左右/高低偏移及镜头倍率。
5. 真网格验证：独立 BVH 检查导出后的实际三角面，不能用生成公式检查自身就说通过。
6. Godot 投影复核、关键过程查看及成本测量。
7. 接真实地形/角色与镜头，再进行少量贴图和装饰验证。
8. 艺术整体、流程和性能均通过后，才冻结生产合同；然后做室内。

先前森林和正式入口不修改。禁止新增连续的左右通道墙。本次局部立体拱体是用户建议的新比较方案；岔口中央的分隔岩体不是连续外侧墙。

| 文件 | 实际职责 |

| `tools/cave_algorithm_lab.py` | 轮廓/路线/投影、108 候选筛选、针对缺口的离线补层、厚拱和混合候选、留出检查 |

## 3. 已证实的错误，不再靠美术补救

- **多个整拱不能独立重叠后当成多个可行走洞口。** 一张拱的实体会挡住另一条路。必须先求所有可见通行开口的并集，再决定结构允许占据的空间。
- **开口并集不能简化成左右极值之间的大矩形。** 这会丢失拱形，并把叉口扩成广场。
- **三岔不能照搬两岔的横向间距。** 以当前合成半宽 2.1m 为例，中央与侧道中心距 3.4m 会使恢复常宽后的通道重叠。中心距必须由两侧半宽和真实分隔构件需要的厚度推导。
- **训练画面补满不能证明算法稳健。** `run-02` 自动补层将训练射线问题降到 0，但留出机位依然暴露缺口，因此拒绝。
- **给平面简单挤出厚度不够。** 若不考虑这一厚度范围内路线的横移，实体会侵入通道；把整个范围过度挖空，又会削掉岔口的小分隔尖端。
- **离散拱体会漏采从单洞分成多洞时出现的薄分隔。** 混合原型在这一局部使用连续形状的中央岩体，不再堆细柱。

## 4. 当前候选的空间算法

所有坐标米制，主轴 +Z；Godot 映射为 -Z。有限五次横移曲线在两端导数为 0，末端仍平行于初始轴，横移保留。正式运行仍须用弧长表驱动速度。

每个纵深位置保留各分支的真实拱形开口，开口是下部直边加上部椭圆弧；自由空间为开口并集。短拱体只可占据该自由空间之外的有限实体带。关键区别：结构与路线使用同一个洞腔，而不是顶石、侧岩各自猜一条边。

混合候选：

- 通道沿轴放短而有厚度的结构块；不是无厚度的大图片，也不是整条连续洞壳。
- 分岔过程中，两洞之间刚出现的薄岩体由同一个自由空间的补集生成。其范围限于各分支中心之间及岔口前后；不能扩大为左右外墙。
- 普通图片装饰以后放在合法结构附近；不承担修复空间拓扑的责任。
- 大小、间距、厚度在当前实验中是候选参数，不作为所有洞穴或场景的通用标准。

## 5. 当前证据与边界

- `run-01`：108 候选，粗检 4 个临时通过，精检全部淘汰。
- `run-02`：离线贪心补层，训练集可清零，留出集失败。
- `run-03`：8 个短厚拱体粗检及两种留出检查，未满足全部条件。
- `loft-screen.json`、`hybrid-screen.json`：比较随路线变化的短拱体及增加中央分隔体的效果。混合方案 1.25m 排布候选的两岔、三岔通过 103 机位的结构筛选。
- `hybrid-camera-envelope.json`：合成镜头横移/升降 ±0.15m，倍率 0.92/1.08 的附加检查，无采样背景缺口。不是扩大正式镜头域的授权。
- `mesh-2way-reduced-01/triangle-audit.json`：实际 81,909 三角面，71 机位，每机位 4,000 射线；背景缺失 0，最差机位的 P99 额外深度约 0.565m。
- 三岔最初的实际网格比公式更差；薄分隔改为解析求交界脊线，再构建局部表面，避免体素抹去尖端。`pipeline-organic-2way-01` 与 `pipeline-organic-3way-01` 均通过当前实际网格筛选。三岔为 245,229 面、71 机位 × 4,000 射线，采样缺失 0、最差机位 P99 额外深度约 0.626m。参考已改为保守距离推进及边界精采样；不能混用旧版本指标。
- `native-03/audit.json`：Godot 实际投影矩阵与离线投影一致。最初直接用 `project_ray_normal` 核对偏轴视锥出现差异，现以真正渲染投影矩阵为准；没有修改正式相机代码。

以上都没有证明艺术表现通过。周期拱重复、贴图风格、真实地形接地、角色队形、岔路内容安全退休、事件/战斗展开、无门和有门的不同生命周期仍需接入验证。室内尚未开始。

## 6. 判定纪律

- `screened` 只是研究筛选，不是 `accepted`。
- 3m P99 深度差是本轮拒绝界线，不是用户认可的视觉标准，不能为了让候选过关临时放宽。
- 有限分辨率、有限镜头和离散参考不能声称连续全域数学证明。
- 当前远端粉色是特意暴露的试验终点，合法远景与外壳缺口分开计算；美术阶段必须制作正确纵深收束，不能照搬粉色终点。
- 雾、压暗、背景色和装饰不能掩盖结构检验失败。
- 找不到可行候选就停在明确失败原因，不能发布一个入口要求用户重新发现已知问题。

## 7. 2D 主导方案恢复比较（未验收）

当前真实源图和原生拼组的最新进度见 [2D 图片最小拼组实验](ART-CARD-TRIAL.md)。下面保留早期数学平面的证据，不得与真实图片准入混淆。

`tools/cave_card_screen.py` 在相同路线/镜头下比较纯平面轮廓，以及平面轮廓加一个岔口分隔连接体。输出 `card-screen-2way-02`、`card-screen-3way-01`。这次不生成全程立体拱层，也不沿通道建墙。

- 每类 4 个间距候选；带连接体的 8 项均通过当前粗筛，无采样背景缺失；这证明此前全程实体拱并非当前粗筛所必需。
- 纯平面候选没有采样背景缺失，但仍有岔口深度跳变问题。不能说它已完全不可行，也不能把零漏空误报为过程通过。
- `native-card-hybrid-01` 已保存同机位合成、仅平面、仅连接体三组图。**分层暴露另一个问题：当前连接体虽局限于岔口，进入时仍能占据画面很大部分，因此不能按“只用了一个模型”称其辅助职责已经合格。** 后续必须缩短它承担的可见结构范围，或改成局部浅片组合；不能用它作为漫长内侧通道面。
- 当前平面只是在白模上用材质标识表面，**不是已经制作好的 2D 美术资产**。椭圆边缘、平切脚部和重复套圈仍未通过艺术要求。不能把这批输出作为用户测试入口、正式资产或 Luna 模板。
- `probe_cave_algorithm_lab.gd --layers` 可以复核各层职责；沿运动选取图，不仅选岔口正中一帧。最终还需加入实际源图轮廓、接地及无模型直道的验证。

下一步限制：先通过真实 2D 源图最小拼组与运动验证，再扩展路段；不继续给完整网格通道换材质、加装饰冒充混合方案。完整模型适配器 `cave_lab_structure.gd` 保留为未接入的研究代码，不在正式入口调用。
