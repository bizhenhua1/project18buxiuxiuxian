# 开发需求与生产合同

版本：2026-09-22。`Dxx` 是开发需求，不因本文存在而变成已完成；当前 C1 有部分未通过原型，实际进度见 benchmark-tasks.json。本次补充为归档与设计合同，不宣称新增功能已实现。

上游：[系统设计](SYSTEM-DESIGN.md)；主题/结构选择：[类型手册](SCENE-ATLAS.md)。目标是让后续执行者处理有限任务、明确输入输出，不再自行解释整套艺术方向。

## 1. 实施边界与遗留代码处理

- **2026-09-23 用户再次明确：大量 2D 美术资产必须仍是主要场景表达，不能把廉价 3D 原型升级为整场建模路线。** 岩片、局部拱顶、侧向体量、根部碎石和悬挂物承担主要轮廓、层次和风格；浅模型仅比较局部厚度或连接难点。空间计算代理不等于可见美术。禁止把“3D 洞壳 + 少量贴花”作为满足本要求的实现。
- 本轮完整立体拱层候选只保留为空间研究对照，未获美术验收，不继续扩大其美术投入或接入正式场景。早期几种平面排列失败不代表 2D 主导路线已被证伪。
- 后续关键机位必须保留 `2D 资产层 / 辅助模型层 / 合成画面` 三种证据，并记录模型用途及可见范围。不能以文件数、三角面少或表面使用图片贴图冒充“2D 主导”；也不捏造用户未给出的百分比门槛。层级切换首先用于识别各层实际承担的视觉职责，不要求关闭辅助层后所有接缝仍通过最终验收。
- 只接最新 Godot 3D 管线。网页 demo 不变，已认可森林构图/布局保留。迁移在独立开关下进行，使用本次冻结的旧行为作为回归参照。
- 不新增连续左右墙。侧岩、柱组、柜组等只能按类型定义承担结构和侧向体量。
- 不修改旧证据的 hash 使其重新有效。历史截图可用于比较，不代表当前版本已通过。
- 复用旧资产标注、提示词存档和捕获工具的有效部分；修改/扩展现有工具优先，不再新建一套名称相似但入口不清的工具。
- 旧 `fit-frame` 只判定有限整框比例问题；旧顶部射线只覆盖部分画面；旧 `capture` 只采集；旧 `freeze` 不具有本案联合约束能力。不得用它们的成功退出替代新要求。
- 旧 JSON 中的故事 `parent` 保留为故事来源；新增结构子类型字段。不能通过改 parent 把题材继承关系一起改坏。

## 2. 三份核心数据与一次编译输出

### A. SceneBrief：设计输入

必填：

| 字段 | 内容 | 缺失时 |
|---|---|---|
| identity | scene_id、故事主题、结构子类型、叙事焦点 | 拒绝编译 |
| route_grammar | R1–R8 组合、节点顺序、入口/出口语义、后续前向策略 | 禁止默认永久发散 |
| spatial_requirements | 可走/战斗/门口/装饰域，净空与支撑需求，队形能否收束 | 不允许仅填统一 width |
| protected_projection | 原构图来源、镜头参数域、角色屏幕锚点/尺度容差来源 | 不可通过自动变 FOV 修复 |
| camera_states | 各阶段允许轨道、朝向域、平移/角速度/加速度限制 | 不可默认固定前瞻量 |
| closure_policy | 每阶段各区域允许背景/要求结构/需要可读性 | 不可默认全屏不透明 |
| lighting_envelope | 正式灯雾、允许最大照明变化、背景色域、曝光策略 | atmospheric/hybrid 不得验收 |
| content_requirements | 功能组、稀有物、可重复物、行程内重现约束 | 不能仅凭结构填满判丰富 |
| event_requirements | 事件及同地点可达后果的 required/possible/none/unknown 战斗能力、交互域、战斗配置 | unknown 阻断发布；可能战斗不得按非战斗布局 |
| corridor_profile / junction_visibility | 错落凹室/缓弯/直道；有门遮挡/无门预览的接管及退休条件 | 不允许默认永久发散或同时铺完整支路 |
| support_rules | 自然地/刚性平台/液面，坡度与接地能力来源 | 禁止继承森林噪声地形 |
| quality_tier | 目标机器/后端/分辨率/预算和允许降级 | 不得写性能已达标 |

数值字段必须有 `source: measured / authored / derived / unmeasured` 及来源。`authored` 表示明确设计选取，不是假装测量；影响兼容性的 `unmeasured` 必须阻断批量生产。

### B. AssetSpec / AssemblySpec：资产与组合能力

扩展现有资产契约，不再靠文件名判断用途：

- `role`、材料/风格标签、源图与提示词/版本/hash。
- 有效轮廓及米制尺寸；图片像素坐标、局部坐标、世界坐标转换约定。
- root 类型：地面接触、表面附着、顶部挂点、纯背景。地面脚点与树冠覆盖分别表示。
- 支撑点/接触多边形、实体足迹、允许悬挑域、开口内轮廓、挂点/接点。
- 合法观察角锥、可否镜像、统一缩放范围、禁止变形轴。
- 显著度、可辨轮廓签名、同屏/沿程复用规则；发光层必须独立可选。
- 组合的父子关系、兼容接点、变体选择、组级轮廓/足迹/最低点/动态包络。
- 表现层选择：单卡片、交叉片、多视角片、浅网格、连续面、仅远景。

**透明图片只能自动提供可见轮廓，不能自动确定支撑或语义。** 首次标注采用源图明亮背景、根点和轮廓叠加审查。已有源图无法看清语义时，不靠截图中的黑影猜测。

### C. TemplateContract：模板适用域

每个模板声明支持的空间子型、路线语法、出口数、机位域、截面域、照明策略、队形和预算。每个输出资产组必须属于该域。

例如 `cave_compact_portals` 可以支持 C1 + R2/R4 + 2/3 出口 + 暗/混合闭合；这不自动意味着支持 C2 的高腔、强顶光、任意环绕镜头。未来扩展必须新增该能力的证据，不能把验证域悄悄写大。

### 编译输出 CompiledScene

统一生成以下数据，不让各消费者再推导不同版本：

1. 世界连续的路线曲线、弧长表、局部标架、节点和 portal。
2. W/B/P/C/D 域、区域归属、碰撞/支撑代理。
3. 镜头状态轨道和允许修正量、关键视线/遮挡约束。
4. 固定 seed 的结构、组合、低装饰实例与稳定 ID。
5. 地面/顶面接口、定向 UV、岔口片、过渡材料及环境归属。
6. 材质/空间分桶、LOD、灯/雾/动态挂物预算与降级数据。
7. 失败/通过的各项检查、适用域、输入依赖 hash 与人工艺术结论。

建议对运行时只暴露小接口：`sample_route(segment_id,s)`、`sample_camera(state,s)`、`query_support(position,kind)`、`query_region(position)`、`get_junction(id)`。CPU 与 shader 的路线数据由同一编译输出生成，禁止再次手写两套圆弧公式。

## 4. 联合编译器的算法级需求

通道、事件及岔路生命周期的详细合同见 [ROUTE-EVENT-CONTRACT.md](ROUTE-EVENT-CONTRACT.md)。下面的 `derive_route_portals_walk_battle_camera_domains()` 必须先由事件后果图推导战斗能力，再保留对齐/展开/交战/离场区，最后联合求解路线、镜头和结构；不能先撒布后临时清场。

扩展既有任务的具体交付：D01 检查事件能力及后果传播；D02 编译有限弯曲/独立左右边界/主轴连续与预览归属；D03 检查入场准备与事件触发门槛；D04 检查缓弯构图和资产视角；D06 联合保留事件空间；D08 做依赖事件与结构的固定组撒布；D09 检查可见卸载和全程遮挡；D12 按该合同第 8 节提交正反例。以上尚需实现及证据，不能由文档更新自动标为通过。

```text
compile(brief, template, asset_catalog):
    validate_declared_domain()
    derive_route_portals_walk_battle_camera_domains()
    build_compatible_structure_and_camera_candidates()
    propagate_clearance_view_angle_connection_and_lighting_constraints()
    for candidate in bounded_candidates:
        solve_finite_route_and_camera_together()
        place_structure_groups_inside_shared_feasible_domains()
        reject_hard_failures_before_dressing()
        score_spatial_identity_composition_and_repetition()
    if no_feasible_candidate:
        return conflict_report_and_precise_missing_capabilities()
    compile_floor_support_and_junction_interfaces()
    scatter_parent_groups_then_conditional_children_with_stable_ids()
    validate_view_envelope_and_allowed_lighting()
    emit_instances_route_camera_regions_budgets_and_evidence()
```

初版不要求一般形式的全局最优解。关键是：变量数量有限、硬约束不被软评分抵消、所有消费者共享结果、无解时可解释。视觉构图分数只用于候选排序，不自动签署艺术验收。

### 密度不以“每 10 米随机多少个”作为唯一输入

结构候选由截面/支持/轮廓决定，再投影到机位域检查层次。对边侧角色记录可见轮廓覆盖和近中远缺口，对低装饰记录覆盖/生境/安静区。世界密度仅是生成参数之一。

方向性采样可用各向异性距离：沿结构走势容许较近，横穿通行方向严格排斥；用空间哈希查询邻居。挂物采用宿主 socket 采样；地表碎物采用表面域采样；二者禁止共享一个“随机世界坐标”流程。

有限候选数和有限局部修复次数应写进配置与报告。预算耗尽立即给出失败集合，不能后台继续生图/截图几小时。艺术调优若两轮对同一失败指标没有改善，报告方法失效，而不是换一个 seed 当进展。

## 5. 资产数量核算器：必须实现而非继续猜

输入：模板关键状态/允许机位、结构角色、已有资产能力、显著度/复用约束、节点旅程、支撑/视角和预算。

输出不是单一总数，而是以下表：

| 字段 | 说明 |
|---|---|
| requirement_id | 例如 `junction3.left_commit.upper_left_structure` |
| role / interface / view | 顶肩/内转接口/所需观察角，不能写泛泛“山洞资产” |
| simultaneous_distinguishable_count | 合法布局最坏镜头中的可辨实例数 |
| reuse_limit / provenance | 同屏上限与依据；未审查的设计假设必须标记 |
| route_recurrence_requirement | 旅程节点顺序及显著主物不得过早重复的要求 |
| compatible_existing | 真正兼容的资产或组及检查记录 |
| required_capabilities | 轮廓/视角/连接/材料等缺失能力 |
| action | 复用、重组、补变体、重制、仅远景、停用引用 |
| estimated_new_sources | 经过组合与共享扣除后的制作源图需求 |
| confidence / unresolved | 确认、设计假设、缺测量，禁止掩盖不确定性 |

算法先做带成本的能力覆盖选择，再检查显著重复与行程重现，最后加入必需叙事组。大量小道具不能抵扣主结构轮廓缺口。近景分辨率由最大投影尺寸与可接受采样质量推导，不能统一把所有图升到 4K。

运行时实例量、原图数量、纹理内存分别核算。例如无压缩 RGBA 纹理基础层内存约为 `w*h*4`，完整 mip 链约多三分之一；最终要按引擎实际格式、压缩、图集与驻留量测量，不能以 PNG 磁盘大小代替显存。

## 6. 生图和资产组织的可执行要求

仅在需求矩阵确定缺口后进入生成。不是每做一个场景就先生成完整背景/整拱。

### 每条生成请求必须带的内容

1. 结构子型与职责，例如“C1 的近左侧层岩主体”，不是只写“黑暗童话山洞”。
2. 形体走势与连接：内轮廓从哪升向哪、在哪与顶岩接、哪些部分必须独立。
3. 观察角/透视：与项目镜头所需角度相容；不能一张画进完整消失点再拿来随处转向。
4. 主材料、线条密度、明度层次、已选风格参考；不得使用参考游戏原图作为可交付资产。
5. 无法分离的固定关系与必须拆出的元素；高重复结构不带灯、晶体、醒目故事标志。
6. 根点/接点/挂点、完整轮廓边界、透明导出要求及禁止裁断部分。
7. 合法变体范围：改变主轮廓/块面关系，保持接口和材料；禁止把换色/镜像记作新形态。
8. 实际需要的像素量与最近观看尺度；每次生成量仅针对当前缺失能力。

提示词模板：

> 为本项目制作【结构子型】的【资产职责】，主题为【材料/叙事】。采用已给定参考的【笔触/线密度/色彩层次】，保留本项目画风。主体走势为【形体方向与轮廓】，接口位于【支撑/连接语义】，从【合法观看方向】观察。该物将作为【独立件/固定组合】使用；【指定配物】不画入主体。要求完整轮廓和可分离背景，禁止【发光/整景透视/对称双拱/文字等具体不适用内容】。变体需要改变【主轮廓】，保持【接口和材料】。生成后仍须通过源图及组合检查，提示词本身不构成质量证明。

这是一份完整字段模板；执行者必须以需求记录填入实际内容，不能带占位符调用生图。不要在本轮触发生图。

### 库组织

沿用现有资源目录，元数据分层保存：共享材料/低显著件、类型结构包、主题装饰包、assembly 配方、模板、编译实例。源图、提示词与批准版本保留关联。停用指撤运行时引用，删除文件前确认无其他景引用。

每资产只维护一个真实来源；共享对象通过 ID 引用，不在 24 个文件夹复制后计成 24 张新图。图集按材质/用途和加载域组织，避免小主题道具迫使加载整套大型图集。

### 三道资产关

1. **单体关**：轮廓、支撑、视角、像素、画风、可分离光层。
2. **组合关**：合法接点、内腔轮廓、组级支撑、左右不机械镜像、主要观察角；这里就应发现 M 顶。
3. **场景关**：已选模板和机位域中的覆盖、重复、层次、明暗与故事功能。

单体关失败不进场景；组合关失败不靠场景遮挡救；场景关失败先定位是模板约束还是局部资产，不盲目重新生成全部图。

## 7. 检查工具的结果要求

| 检查 | 自动部分 | 仍需判断的部分 | 失败输出 |
|---|---|---|---|
| route-contract | 连通、弧长、端点/切线、扫掠交叠、区域 owner | 行进节奏与节点期待 | 最小失败段、冲突域、消费者版本 |
| asset-capability | alpha/尺寸/采样、标注完整、视角兼容、插槽 | 材料/笔触/形体是否匹配 | 源图标注叠图与缺失能力 |
| assembly-shape | 内轮廓、净空、接点、足迹、组观察角 | 天然轮廓/人工秩序是否合理 | 明亮背景单组多角度结果，不先跑整个地图 |
| camera-envelope | 近面碰撞、机位越界、投影锚点、转向速度 | 运镜是否自然、有无眩晕 | 失败时间区间、屏幕区域、所需余量 |
| closure | 语义区 alpha/ID/depth、背景连通域、照明域、动态包络 | 正式效果是否自然 | 缺口角色归因，允许背景与错误孔洞分开 |
| support-ground | 多点支撑残差、坡度、液面交界、定向 UV 相位 | 贴地融合自然程度 | 支撑点差值、对应材料/区域 |
| richness | 轮廓重现/频率、角色层次、必需功能组存在性 | 是否有氛围与记忆，是否过嘈杂 | 缺少结构能力还是叙事层，不仅报资产数 |
| performance | 分阶段帧时间、绘制/过绘、驻留/上传、灯/粒子上界 | 哪类降级可接受 | 成本归因及保留视觉层次的降级选项 |

所有检查分 `passed / failed / unmeasured / not_applicable`。不能将工具未支持解释成通过。颜色亮度/对比度阈值必须对应实际色彩空间与曝光，不能用未经说明的 RGB 差值作物理结论。

## 8. 验收矩阵：少做无用截图，但不遗漏关键变化

模板须覆盖：普通行进、2/3 岔接近与选择、左右/中路穿口、内部展开、战斗、离场和下一段接续。选择动态变化最大区间进行连续回放，静态截图只保留关键证据。风、挂物、雾的变化需要有限动态回放或保守包络。

视口只测试声明支持的边界和代表点；不能测了两个宽高比就宣称任意分辨率支持。机位/照明超出许可域时运行时应使用已声明的安全约束或报告配置错误，不能突然跳镜头或生成大板挡住。

每次修改由依赖图决定重检范围：

- 改源图：该资产、包含它的组、实际引用组的模板/镜头。
- 改某类机位：该机位域与它依赖的顶角/角色投影检查。
- 改通用路线编译：所有路线语法的少量代表用例；通过后再按需要验特例。
- 改某主题装饰：不触碰森林全量重拍。

允许几何/数据检查自动批跑，但不得把人工注意力耗在重复看全部地图。截图数量和耗时不是进度指标。

## 9. 制作顺序与阶段交付

### 第一阶段：先证明共同设计可行

完成 D00–D06 的必要部分，以现有合法模块或中性代理测试紧凑洞穴的 **路线—小口—机位—截面**。代理只用于约束测试，不能冒充美术成品。若机位/队形/门洞无解，此阶段就报告，不生成几十张资产。

交付：失败/可行区间、统一路线演示、机位域、首批需求矩阵和明确补图清单。

### 第二阶段：一个真正的紧凑洞穴代表段

只补清单里的能力，完成 D07–D12，交付正式连续体验及可重用的模板/资产组/验收记录。森林不改。洞穴未获认可，不批量套向其他场景。

### 第三阶段：验证不能从洞穴继承的能力

按差异而非场景名字排任务：

1. 低顶居所：亮顶、家具支撑、吊物。
2. 工程拱道与礼仪高廊：工程连接/水坡、柱拱尺度分别验。
3. 高洞与活体腔室：高度层次、肋膜附着分别验。
4. 街庭/湿地与桥：人工秩序、水陆与允许开空分别验。
5. 工坊/厨房、剧院/钟楼、镜像/错尺：功能组、特殊拓扑及额外效果逐项验。

可共享已冻结能力，不能声称一个低顶房间证明所有室内。每类是否需要新代码由能力差异决定，不强行一类一个新系统。

### 第四阶段：24 景内容生产

按类型手册逐景填主题需求与能力差异；已覆盖部分复用，缺失部分形成小工单。每景仍需正式体验审查，但不再从零推理岔路/屋顶/机位。跨主题连接要检查端面、净空、UV、区域光雾和预加载。

## 10. 执行者的停止条件与问题登记

以下情况立即暂停依赖该问题的制作，不停止可独立完成的明确任务：

- 无解的玩法/机位/结构组合；输出冲突与 2–3 个有代价说明的替代方案。
- 缺少关键资产能力；输出准确角色/视角/接口/像素需求，进入补图或重制流程。
- 某规范缺定义；登记 `SPEC_GAP`，说明影响范围，不自行扩大为全作默认规则。
- 预算超限且会伤及主轮廓/可读性；交付成本报告和可选择降级，不无限优化。
- 两轮同一问题无实质改善；登记失败方法及为何失效，不重复随机重试。

问题记录必须有：ID、模板/场景、最小复现、关联约束、实测与假设、已试方法、可选解决路径、未受影响工作、关闭证据。写完方案不关闭问题；代码通过但未视觉认可标为 `implemented_awaiting_visual_review`。
