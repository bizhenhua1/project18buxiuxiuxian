## 1. 最终要交付的东西

交付一个能反复走完的 C1 岩洞样例，而非一张漂亮入口截图：

**紧凑直段 → 远处看见小入口 → 小范围内选择 → 穿过侧口/中口 → 稳定前向的内部通道 → 局部展开并战斗 → 离场接下一段。**

同一个样例支持二岔和三岔、全部出口、固定可复现布局。树立的标准包含：空间模板、镜头状态、资产/组合契约、撒布规则、光雾地面、检查工具及生产清单。完成后再用差异表完善其他类型，禁止先把洞穴复制到 24 景。

### 本轮拆解与后续实现的区别

初始拆解建立下面的决定、公式、任务、交付和停止条件；当前已有未通过的运行试验，没有批准新资产。工单按 B00–B11 的依赖执行。完成设计与代码通过，都不能代替用户对最终岩洞视觉的认可。

## 2. 首个样例的固定艺术决定

| 项目 | 决定 | 不能悄悄改成 |
|---|---|---|
| 空间气质 | 天然、紧凑、不规则，有近侧体量，顶高可被角色尺度理解 | 高拱宫殿、维护下水道、空旷大溶洞 |
| 材料 | 克制的冷灰层岩，层理有方向；少量湿润区 | 每块岩体烘焙亮晶体、泛蓝发光满屏 |
| 结构 | 中等岩组为主，侧岩、肩岩、顶岩、岩根分工；大完整拱只作非必需地标 | 大拱拉宽填岔路；一张肩岩镜像成 M 顶 |
| 近侧 | 宽厚且高的独立岩体/组合，和临路岩体一致 | 两根细柱；新增连续左右墙 |
| 顶部 | 近处组装顶岩，远处用同材料色系背景/雾衔接；采用 hybrid | 巨大水平补顶面、把近处缺口压黑 |
| 岔前 | 入口可读、分隔岩仍在、原通道未骤然变广场 | 一次性展开三条支路全部宽度 |
| 镜头 | 保护既有离轴投影和人物占比；转向服从穿口安全域 | 用任意广角、升高眼位或放大人物遮问题 |
| 生活/叙事 | 渗水处、遗留营地、封闭旧入口三种功能组合设计；一次普通段不同时塞满 | 以增加碎石张数代替记忆点 |
| 动态 | 少量有来源滴水/尘粒、保留曲雾的形态语言 | 所有岩片摆动、每个亮物都建实时灯 |

上述颜色描述是制作方向，不宣称现有资产已满足；需在源图/组合审查时冻结实际材料样本。

## 4. 样例拓扑和空间域

建立以下节点，以语义命名，不用单一距离阈值兼任全部状态：

| 节点 | 拥有什么 | 玩家应感受到什么 |
|---|---|---|
| A 接近段 | 普通走廊、近侧岩、第一层顶岩 | 正在山洞内行走，前方有去处 |
| B 选择段 | 2/3 个出口孔、分隔岩、交互选择区 | 能选择，脚下仍紧凑 |
| C 穿口段 | 单个 portal、短喉部、内外侧转角组 | 有穿入另一空间的过程 |
| D 恢复段 | 有限侧移结束、出口前向、常规机位恢复 | 重新沿直通道前进，不持续斜走 |
| E 展开段 | 独立战斗域 B、角色入位路线 | 门后适度展开，有安全交战空间 |
| F 接续段 | 与下一段相容的端面、环境过渡与稳定 ID | 世界连续，没有瞬移/地砖重置 |

选择节点只拥有共享前区与出口接口；支路从自己的接口后接管结构与地面。分隔岩的脚印从各通行扫掠域之外求得，不能先铺岩再强行挪路线。

三岔入口必须可区分，但无需左右和中间同一纵深。若横向挤不下，先调整入口前后错位和局部朝向；超过紧凑模板可行域则拒绝。不能自动扩大到三套完整走廊的外包矩形。

## 5. 路线算法：首版采用明确可推导的有限侧移

首版不写一般迷宫求解器。对朝前继续的左右支路使用以下五次侧移模板：

```text
t ∈ [0,1]
q(t) = 10t³ − 15t⁴ + 6t⁵
x(t) = d · q(t)
z(t) = L · t
```

这是本案选定模板的直接数学定义：d 为有符号侧移，L 为前向过渡长度。入口与出口横向导数、二阶导数均为 0，前向持续推进。结束后沿 x=d 的稳定前向接直段，**不跳回 x=0**。真实转向的其他模板后续另建。

相机和角色都不能直接把 t 当时间。对曲线建立弧长表，按实际速度推进 s，再反求 t。沿线位置、切线、横向标架、宽高和区域 ID 一起返回。

### 参数约束

- 最大路线偏角由 `atan(1.875 · |d| / L)` 得到，可据动作转向与镜头可行域反推最短 L。
- 曲率由 `|L·d·q''| / (L²+(d·q')²)^(3/2)` 求得；检查局部 `|κ|·w < 1` 和全局扫掠自交。局部条件不是全局无交叉证明。
- 入口位置/方向选在曲线满足相应约束的区段；不能先任意放门再要求路线瞬间穿过。
- 行程时长来自弧长和既有速度。超过选定体验节奏则重新选 d/L/门位置，不提高跑步倍率。
- 共享前区允许支路路线重叠；过各自 portal 后的通行域不得再次错误相交。路面、道具归属使用节点拓扑，不按最近曲线随意切换。

首版只支持这个有限侧移模板及中路直通；由需求证明需要曲门/真实转向时，再增加另一类。不能为首个标杆先做通用任意曲线编辑器。

## 6. 队形与镜头算法必须一起验

### 通行队形

从当前角色控制器读取实际行进单位、碰撞/动画扫掠和所持道具包络，不能以战斗列宽代替行进宽度。若当前队形已经能穿口，就不新增收束机制；否则采用连续编队收束、通过、恢复。成员沿自己的合法路线按距离移动，不直接横向插值穿过门侧岩。

角色全部通过、入场路径可达、战斗域和机位就绪分别记录。`chamber_ready` 由这些条件共同成立产生，不由单一计时器到点产生。

### 镜头轨道

1. 保留入口/常规/战斗的现有投影配置来源，获取实际 lens、horizon、height 和允许调校范围。
2. 定义五个镜头约束状态：选择前、接近选中口、穿口观察域、出口恢复、战斗稳定。
3. 每状态只优化少量变量：沿线跟随偏移、横向偏移、朝向偏移。投影参数不作为补缝优化变量。
4. 以 portal 的有符号距离、视线可达及相机观察域定义状态进度；不是“选了左就立即瞄向左路远端”。
5. 预编译平滑轨道，限制速度/角速度/加速度。帧率变化不会改变轨道；运行时只查表和处理已有平滑跟随。
6. 轨道与结构联合检查：近裁剪安全、上下角覆盖、卡片观察角、出口识别、角色屏幕大小。任何一项无解都返回候选层，不用加大顶来掩盖。

合法结果可以是角色已开始偏向左、镜头仍略朝原前方；镜头随后在门侧岩持续提供框景时完成转向。延迟量由安全观察域求得，不写死一个适用全部门的时间。

## 7. 资产和组装：先决定能力，再决定几张图

| 槽位 | 需要的能力 | 组合关系 | 拒绝条件 |
|---|---|---|---|
| 临路侧岩 | 表达主岩壁与坡脚，正视及有限斜视可用 | 与岩根、肩岩连接 | 烘焙整景透视；薄片侧面进入主视域 |
| 近侧填充岩 | 少量形成左右大体量，轮廓宽厚竖向 | 跟临路侧岩同材料，可部分遮挡它 | 只靠巨大缩放；新造连续墙 |
| 左/右肩岩能力 | 从支撑处向内上方收束 | 接顶岩，可错深度 | 镜像拼接必然形成 M 型内轮廓 |
| 顶岩 | 中央与转角上部接续，有可辨变化 | 依附结构组，不虚构地面脚点 | 固定醒目钟乳/晶体高频复制 |
| 内/外转角组 | 在穿口机位域内遮住结构侧面和角空 | 分别属于共享节点或支路 | 一张完整拱充当任意转角 |
| 入口分隔组 | 把 2/3 个出口读成独立孔 | 由实际路线扫掠剩余域生成 | 侵入角色路；挡住必要选择标识 |
| 低层过渡簇 | 接根、碎石、湿迹 | 层理/重力/水流方向决定 | 普通地面随机噪点铺满 |
| 功能组 | 渗水、遗留营地、旧封口 | 主物+附属物+支撑/来源 | 有小物无用途；每一段重复同一故事焦点 |
| 独立强调层 | 晶体/灯/滴落来源 | 绑定合法宿主，有显著复用限制 | 主结构加密时亮点同步加密 |

上述九行是**能力槽位，不是九张图**。同一张合法侧岩可以服务多个槽位；某一槽位也可能需要多视角/多个轮廓。

先编译关键机位需求，记录最坏同屏可辨数 n 和被审查的重复限额 r，再得到 `ceil(n/r)` 的轮廓下限；加入观察角/接口、旅程重现和功能组约束后求制作清单。低显著碎石组与显著完整钟乳不能使用同一 r。

### 单组预检图必须先于全场截图

只渲染一个岩组：正前、该组允许观察角两端、相邻组拼接、亮背景和正式材质。检查内拱线、支撑、左右一致性和接口。若 M 顶/假悬空在这里出现，就撤回组；不得进场景后再靠雾消除。

旧 `shoulder-rising-v3`、`side-fill-v1` 和其他素材只进入候选库；不预先宣布可用或全部报废。

关键能力缺图时，B04 可提供显式标为代理的参数轮廓供 B05 求几何可行域；这只允许形成 B06 的精确制作需求，不算美术通过。新图到位后必须回验相关组合及可行域，代理的覆盖结果不能沿用为成图证据。

## 8. 撒布算法：四层生成而非统一随机

1. **空间骨架层**：路边主结构、近侧质量、分隔岩、门侧/转角组，由路线、机位与截面共同求得。
2. **方向性结构层**：层岩走势、肩顶接续、近中远轮廓。结构沿弧长递进，但左右组不强制同深度、同尺寸。
3. **生境与功能层**：渗水依湿域、碎屑依坡脚、营地依可支撑停驻面；采用父组先行、子件条件生成。
4. **强调与物效层**：从合格宿主中选择少数焦点，受同屏显著数、沿程间距和预算共同限制。

结构间距不是先写一个 65U：每组投影轮廓在允许机位中的覆盖和重叠决定可用间隔，再用方向场和受限抖动避免机械节拍。必须保留有意的安静区域和出口可读区，不能只优化“填满率”。

实例 ID 由段/节点/角色/槽位/变体种子组成。镜头移动不重新随机、不改变布局；流式复进区域应得到相同实例。LOD 切换不改变根点或组合身份。

## 9. 顶角、背景、地面、光雾的首例策略

- 顶部及两上角分别标注必须结构区和可接远背景区。从真实离轴投影反求射线；近水平射线转交远端结构/背景，不能求无限大平顶。
- 左右填充检查实际可见 alpha 和观察角；物体的矩形边界覆盖画幅不等于画面没有洞。
- 地面以自然无明显方向层岩为主，路径、支撑和湿域有共同 region。额外用简单方向标尺检查转后路线轴，不能靠天然纹理不明显忽略方向错误。
- 近处支撑平面与碎石软过渡分开，角色经过区域不受装饰网格随机抬高。
- 背景与远岩采用同一材料色系的低频颜色；正式照明和允许最亮技能都需成立。明亮无雾是诊断，不自动要求所有远景几何封闭。
- 保留曲雾外形，但限制重叠面积及角色穿插；软交接是否适用于当前渲染器需实测。不将调低整屏亮度作为遮错工具。

## 10. 验收包：一个样例覆盖哪些情况

### 空间与过程

二岔左/右、三岔左/中/右，共五条出口过程。每条连续记录 A–F，不做五套独立手摆场景。同一实例布局同时提供正式、诊断和允许照明上界三种观察模式。

对每条路线记录入口可读、选择、侧移、穿口、前向恢复、战斗、接续的状态事实。关键帧由状态和覆盖风险峰值提取，不固定等间隔拍照冒充完整检查。

### 必须通过的判定

| Gate | 判定 |
|---|---|
| G0 保护 | 森林未被改变；人物投影基准有来源，镜头调校域已声明 |
| G1 路线 | 段落连续、有限侧移、同一数据驱动地面/角色/镜头；没有永久斜路 |
| G2 通行 | 角色及道具实际扫掠可通过门；没有滑步加速或瞬移收束 |
| G3 紧凑气质 | 直段/岔前无大空场，门口与内部展开可辨，近侧体量充分；需要视觉认可 |
| G4 组装 | 无拉宽整拱、机械 M 顶、明显悬空；合格视角域覆盖实际机位 |
| G5 覆盖 | 上/左右/两上角逐区通过；正式/允许光照下没有错误高对比露空 |
| G6 丰富度 | 结构变体、层次与功能组共同成立；显著亮点不随结构数量增长 |
| G7 运动稳定 | 镜头、布局、雾、LOD 与场景接续不跳变；抽样和连续证明范围分别标记 |
| G8 成本 | 固定平台/配置下记录旅行与既有代表战斗负载，成本可归因；不给未测技能负载承诺 |
| G9 生产闭环 | 从主题配置和资产契约重新编译能复现；所有关键结果非手动摆图 |

种子测试采用一个固定基准加预先选定的反例/极端布局种子；不能不断换 seed 直到出现一张好图。精确种子和边界视口在 B00/B05 固定，并记录为何覆盖风险。超出域的镜头设置应被禁止或明确标未支持，不靠突然跳镜头补救。

| B03 | 选择/穿口/恢复的参数化镜头域；保护投影 | B00/B01 | `camera-contract.json`，供联合求解的候选域，尚非闭合批准 |
| B04 | 候选资产逐项能力检查，建立最小岩组与正反例 | B00 | `asset-capabilities.json`、`assembly-check.json`；单组拒绝 M 顶 |

## 12. 举一反三：首例之后具体迁移什么

每种类型保留四栏：**可继承、须重新参数化、必须新增、不得继承**。这比复制一份配置再改颜色更可检查。

| 后续代表类型 | 可继承的算法 | 必须新增或重验的差异 | 严禁照搬 |
|---|---|---|---|
| I1 低顶居所 | 有限侧移、门后展开、机位域、支撑/覆盖检查 | 亮近顶连续材料、家具多点支撑、生活组、挂点与摆动扫掠 | 岩肩拱形、碎石地形、洞雾密度 |
| A1 下水道 | 节点 owner、入口语法、地面局部轴 | 拱券接点、侧台/渠道、定向坡向、液面、维护组 | 天然岩体随机旋转、森林起伏 |
| A2 宫殿 | 构图保护、层次/显著复用分析 | 柱冠比例、仪式轴线、宽而不空的中景结构、顶肋与吊饰 | 小洞的近顶高度、紧凑孔径强行套大厅 |
| C2 高大洞穴 | 组级轮廓、方向场、有限过渡、远背景衔接 | 近脚参照/中层结构/远高顶分层、竖向光雾、局部平台 | 把 C1 全部等比放大、把顶高直接变路宽 |
| X1 鲸腹 | 小孔入腔、owner、镜头观察域 | 肋膜挂接、刚软分离、脉动包络、湿迹和角色光色 | 岩石层理、石洞地面、对称整环复制 |
| O3/O4 庭园/街巷 | 稳定 ID、功能组、路线与镜头协同 | 人工园圃/街道秩序、天空/檐口语义、局部铺装 | 顶部闭合规则、洞口式全部出口 |
| O2/R7 湿地/桥 | 区域、支撑、允许空域检查 | 水陆/桥台/平台连接、侧空安全、透明层成本 | 用岩体填满合法水面/桥外天空 |
| V1/V2 剧院/钟楼 | 机位域、挂点、预算、实例归属 | 台口/后台或平台拓扑、绳轮、垂直空间、设备运动 | 单条地面长通道假冒全部空间 |
| X2/X3 镜廊/错尺 | 区域所有权、门后过渡、构图保护 | 反射能力及预算；遮挡下明确重映射；真假门语义 | 用漏空/瞬移 bug 充当诡异效果 |

森林保持保护；若通用路线接口最终接回森林，必须单独证明原视效和已认可路线体验不受破坏，而不是自动替换。

迁移次序推荐：I1 验证最不同的顶/家具约束 → A1 验证工程与水 → C2/X1 验证高空间/有机体 → 其余按能力差异扩展。顺序由依赖决定，不一口气查看 24 景。

## 13. 交给 Luna 前必须到什么程度

首例在 Astra 阶段解决未知的共同设计问题；交给 Luna 的每单必须具备：固定输入/适用域、具体改动模块、禁止修改项、算法/字段定义、明确输出、自动检查与视觉反例、失败时回到哪一单。

Luna 可以在已证实模板内接入主题、标注资产、补明确变体、实现已定义差异和运行增量检查。不能把“做一个新类型并自行思考所有空间规则”包装成普通资产工单。

B11 必须附一项迁移验证：选择与 C1 明显不同的 I1 小样，证明通用接口能复用、洞穴专属规则能关闭、家具/顶/挂物差异能独立进入。它只证明接口扩展，不自动批准 I1 美术；这一步能暴露所谓通用算法是否实际写死岩洞。

首例完成时应能明确回答：哪几种路线/机位/光照域已通过、哪些资产能力可复用、最小库怎样推导、哪类失败能在生图前发现、其他类型还有哪条新增约束。不能以“可套所有场景”替代这张清单。
