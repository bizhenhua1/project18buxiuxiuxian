# 通道组织、岔路生命周期与事件前置约束

日期：2026-09-22。状态：**用户意图已确认并纳入设计；本文件所列新增算法与检查尚未全部实现。**
核心图像依据：[核心参考文档](../references/CORE-REFERENCES.md)，包括原 11 张参考游戏截图和用户两张空间示意。首例 C1 的资产准入失败仍未关闭。

## 已确认的产品边界

- 正式游玩不允许玩家自由旋转或缩放镜头；探索、过口、事件和战斗镜头由系统控制。调试镜头不扩大正式支持范围。
- 不允许在行进中的任意位置突然原地开战。所有战斗必须落在提前准备、具备战斗能力的事件区域，包括可能战斗的交互后果。
- 侧视不是用户要求采用的表现手段，15°只是“确有侧视必要时要受限”的举例，**撤销此前把 15°作为首轮默认上限的约定**。不把使用侧视、达到某个侧视角度或支持侧视作为模板的必做目标。

## 1. 单通道的两种变化，分开控制三条线

用户单通道图左侧：总体向前，左右边界可以局部错开、凹进、凸出，形成岩窝、柱间、货架退台、较窄的一段和单侧的停驻空间。示意的直角表示组织关系，不强迫自然洞穴做直角岩壁；不是新增连续左右墙的授权。

右侧：边界及必要的行进中心线缓慢弯曲，制造前后遮挡、侧面逐渐显露、远景时隐时现。它不意味着同一正弦周期的左右边界，也不意味着通道无限改变总体方向。

必须分离：

1. **视觉边界**：结构内缘及其高低、伸出、退让，决定包围和节奏。
2. **通行路线**：人物和携带物实际可通过的平滑轨迹；边界有凹室时可以仍然走直线。
3. **镜头轨迹**：在人物画幅位置、结构合法观察角、遮挡和运动舒适度共同约束下前进；不逐点追随边界，也不必逐帧等于路线切线。

三者共享同一份空间合同，但不能用同一条抖动曲线替代。天然洞的凹室可以由侧岩/根部组合表达；室内通过柱距、家具组和梁格表达；森林通过树簇与冠缘表达。

## 2. 统一的路线表示与生成顺序

### 2.1 有限变化，主轴不漂移

每段声明前向轴 e、横向轴 n、起点 O。以纵向参数 u 写候选通行中心：

`p(u) = O + u·e + d(u)·n`

- d(u) 使用具有有限支撑的样条段或形状片段，不使用无限累积的随机航向。
- 接口至少位置、切线连续；非显式转向节点的出口切线恢复主轴方向。为平顺移动，镜头轨迹还需速度/加速度约束。
- 数值累计 `S(u)=∫|p'(v)|dv` 后建立弧长查表，移动以 S 采样，禁止把 u 直接当真实路程导致弯道速度变化。
- 左右宽度 `wL(u)、wR(u)` 独立于 d(u)。侧室通常优先改变一侧宽度/组退让，不必改变人物轨迹。
- 相邻趋势段可以是挤压、侧室、缓弯、平静直段，选择由类型与事件决定。形状随机种子可复现；不能每隔固定距离同步切换全部层级。
- 需检查轨迹自交、近邻边界交叉、走廊过窄、相机近面/角色装备扫掠。边界的短阶梯变化由组间遮叠或本类型连接组表达，人物和相机不做阶梯跳跃。

### 2.2 先事件功能，再路线，再撒布

编译顺序：

`事件图及可能后果 → 功能保留区 → 通道/岔口候选 → 镜头和结构联合求解 → 功能组 → 装饰与光雾 → 验证及固定布局`

这里的撒布不是先铺满、再删除事件周围的东西。结构会参与联合求解，最终装饰服从已确定的通行域、战斗域、镜头域、事件交互域和遮挡规则。

## 3. 岔路：门遮挡与可见预览两种合同

| 类型 | 选择前 | 选中及进入 | 后续 |
|---|---|---|---|
| 有门/可靠遮挡 | 小选择区＋多个可达入口；闭门后不要求完整子场景可见 | 遮挡成立时预载选中场景，开门或穿口过程中保持位置、尺度、光照和地面连接连续 | 可互斥复用同一空间；不同时渲染/启用重叠的完整子场景 |
| 无门/能看远景 | 每条可见选项有入口、短过渡、可信纵深；侧口很快回到相同主轴方向 | 选中后将该预览连续接成真实通道，保留仍在可见域中的其他预览 | 未选内容在被遮挡/离开允许视野后退休；后续只有选中通道保持完整活动 |

恢复轴向允许保留横向偏移，不能强迫角色走回原中线。需要坐标重定位时，必须保证所有相关对象和参考系一致，禁止可见画面跳动。门遮挡允许空间复用，不要求采用昂贵的多世界实时 portal 渲染；具体方案由已有引擎管线和预算选择。

生命周期：`preview → selected/preparing → traversing → committed → unselected_retiring → successor_active`。点击选择与可靠遮挡不是同一时刻。若未选预览仍可见，就保留到安全退休点；不能露出空洞，也不能以移除支路突然减少雾或照明。

视觉预览不得意外启用完整敌人 AI、战斗碰撞、奖励和事件副作用。选中内容保持稳定 ID/种子/材质相位，不能从预览替换到正式时换造型。若预览已可看见交互对象，其视觉与后续实体必须一致。

## 4. 事件能力合同：不能只看事件名称

| 能力分类 | 事件例子 | 必须预留 | 可放宽项 |
|---|---|---|---|
| required 战斗必发 | 普通遭遇、首领战 | 稳定直道战斗段、站位/前移/来敌走廊、镜头构图和关键视觉区 | 外围轮廓可不规则，不能把全图铺成矩形广场 |
| possible 可能战斗 | 有敌对选项、交易失败开战、剧情伏击、连锁事件可能交战 | 与 required 相同的战斗能力，须在触发前形成 | 即使最终和平解决，也不临时撤除该段结构 |
| none 确认不战斗 | 纯购买、纯升级、纯剧情、休整 | 可达路线、停驻/交互范围、焦点视线、镜头和通行净空 | 可以侧凹、偏置、缓弯，站位不必符合战斗列阵 |
| unknown 未声明 | 后果表缺失、插件事件未标能力 | 阻断发布编译并报告缺项 | 仅明确的开发预览可临时采用保守战斗布局，不能按 none 静默继续 |

`possible` 必须包含可达的选项、失败后果、条件触发和同地点连锁后果。出现循环时用访问集合/固定点传播计算能力；跳转到另一个地点的战斗由目的节点承担，不无条件把全作所有前置事件都变成战场。

选择事件类型后再“抽到会战斗”的系统，需要事先声明该位置的可抽取集合：若集合里包含交战，位置必须已具备战斗能力；若位置只有非战斗能力，就只允许抽匹配的事件。不得等抽签结果出来后重排眼前的岩石。

## 5. 战斗段不仅是事件中心的一小块空地

战斗合同按过程保留：

`弯曲/岔口 → 平顺对齐段 → 入场及展开段 → 稳定交战段 → 离场过渡 → 恢复探索变化`

- 对齐段在事件激活之前完成；不能在弯道里立即切到直线战斗机位。
- 战斗段长度/宽度取自当前战斗模式：队伍列、装备包络、允许前移极限、敌人接近、攻击表现和撤退/倒地/重生需求。不能仅凭一个“战斗半径”覆盖全部需求。
- 无限贯通技能不意味着无限清空地表：逻辑命中沿既有战斗域处理，画面按视距/雾/特效预算截取；不能用这个技能把洞穴加宽或延伸为无限渲染走廊。
- 交战所需地面是满足约定坡度/支撑的规整区域；外围仍可有岩肩、侧凹、顶高变化、远景小口。规整的是玩法与主要视线，不是把四周做成空旷矩形。
- 顶体和吊物的最低点与遮挡必须覆盖允许的战斗机位、技能亮光及角色动作；无战斗事件也仍需满足自身的照明/视角约束。
- 战斗触发条件至少包含 `layout_ready && route_aligned && party_ready && camera_ready && assets_ready`。阈值由模板的实际构图/运动合同提供，不写任意全局秒数。未准备好时在已设计的接近流程中等候，禁止触发后瞬移或临时重建。
- 可能战斗事件在交互开始前完成准备，不依赖玩家点下敌对选项后争抢加载时间。
- 同一位置的多个可能战斗配置取兼容需求并集；无可行解时更换该位置事件候选或返回设计冲突，不偷偷扩成大广场。

## 6. 资产与镜头的联合限制

默认通过受控的路线、镜头、入口位置和固定资产组合维持适合源图的正面阅读，不依赖把薄片斜着展示来构建空间。不得把 15°写成全局参数、默认容差或用户验收数字。

只有具体方案确实需要侧视时，才说明必要性，并针对该资产、组合和实际机位验证允许范围。观察角诊断仍用于发现意外压扁/穿帮，但它是质量检查，不是要求每个模板都引入侧视的设计条件。也不把“正面阅读”误解为所有资产每帧面向相机旋转。

对实际眼点到可见结构的视线检查角度。单通道缓弯、选择时的横移、战斗镜头均纳入；不能只比较路线/相机 yaw。左右宽度变化和近侧填充位置都会改变这个角度。

当约束冲突时，只在已声明范围内依次寻找可行的路线/镜头/固定组合配置，保留角色构图；需要侧面能力则使用经检验的多面固定组或替换源图。禁止每帧让承重结构追着镜头旋转、拉宽图像补投影压缩、临时淡出露洞。

## 7. 数据与代码交付要求

SceneBrief 增加：

- `corridor_profile`: `stepped_recess / smooth_meander / mixed / straight`，主轴和允许偏移/曲率/截面变化域、类型语义。
- `junction_visibility`: `door_occluded / open_preview`，预览范围、选中接管接口、遮挡证据和退休条件。
- `event_requirements[]`: event_id、同地点后果图、`combat_capability: required/possible/none/unknown`、交互域、战斗配置引用、来源/版本。

CompiledScene 增加：

- `event_zones[]`：事件的稳定 ID、沿弧长的 approach/align/deploy/active/exit 范围、所属路线、许可镜头状态和 readiness 条件。
- `branch_lifecycle[]`：预览对象、实际内容、活动模拟域、遮挡退休依赖，不把所有支路都作为完整活动场景。
- `placement_reasons[]`：实例属于何种结构/事件/地脚/调剂角色、依附何组、为什么不侵入保留域。
- `constraint_findings[]`：视角、净空、支撑、事件能力、重复、可见卸载等通过/失败与证据；设计声明不等于实测通过。

接入既有 D01/D02/D03/D04/D06/D08/D09/D12，不新造一套平行生产工具。编译期分配功能域和固定资产；运行期按已编译路线采样、状态切换和空间分批加载，不每帧重做撒布求解。

## 8. 最小验收集

1. 左右退台通道：边界变化，角色可保持直行；无阶梯移动/镜头跳变，凹室不产生无意第二条路线。
2. 柔和缓弯：主轴稳定、弧长速度稳定、地面纹理连续，近侧资产和上角在全程视域内符合约束。
3. 缓弯进入必发战斗：到触发点前已完成对齐、展开、镜头及资源准备，触发时环境不重排。
4. 可能战斗：分别走和平、敌对和同地点连锁后果，使用同一预布置环境；和平结果不强制开战。
5. 非战斗凹室：商店/升级/剧情各检查焦点、交互和离开路径，不为了复用战斗模板扩大空间。
6. 有门二/三选：闭门后内容互斥准备，开门连续显露；未选场景不发生 AI/奖励/照明副作用。
7. 无门二/三选：每个出口预览可信、接管连续、未选内容在可见时不消失，移除后不漏空；恢复轴向不强制返回原中线。
8. 边界情况：事件能力缺失、两个功能区重叠、所需直段不足、近侧超观察角、加载未就绪，均返回具体冲突或进入既定等待状态，不能自动拉图/改 FOV/临时清场。

上述为新需求的验收定义，不是已通过的报告。首例优先验证其自身需要的退台/缓弯、无门岔路和战斗预留；有门能力单独列证据，不能由无门截图推定通过。
